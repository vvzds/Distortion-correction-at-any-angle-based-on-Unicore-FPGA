## 证据链与方法

1. 输入 FDC 末尾只有既定模块级 `PAP_GROUP` 约束，RTL/IP/原运行输入及回执产物哈希再次核对通过。
2. 已被原回执收录的综合网表 `undistort_map` 模块提供 N78/N82 实例清单；源码第 79/80 行分别是 `fx*xd7`、`fy*yd7`，后续第 193/194 行写入 sx8/sy8。综合网表中的 APM 实例保留相应源码行标记。完整树清单不依赖名字相邻或坐标接近来判断属性。
3. 本机原始 `.dmr` Logical Constraint 表也列出两树各 207 条目标对象属性，但 `.dmr` 不在旧回执后缀清单，故只作为辅助证据。
4. 将现存 map/pnr ADF 复制到独立核查目录，复制前后校验字节；用本机 PDS 2022.2-SP6.4 的原生 `.switch_db` 转为 ADIF 文本，读取实际 `INSTANCE` 内部的直接 `ATTRIBUTE PAP_GROUP` 节点。所有成功导出的退出码、原始日志、工具哈希、输入数据库和输出文本哈希留档。没有执行 compile/synthesize/pnr，没有修改或烧录生产固件。
5. 解析器使用括号结构隔离实例属性，不能借用相邻实例或嵌套子节点的属性；按综合网表清单核对完整覆盖，并与旧哈希锚定的 `binding_groups.fdc` 中 10 个布局实例交叉核对。新导出文本附全文，不把自己拼装的 FDC 冒充 PDS 原生导出。
