# 回传要求与验收标准

每名协作者同一阶段只交一个ZIP：报告、修改后的审验工具/完整diff、所有必要输入或精确已交身份索引、命令/日志、原生结果/失败尝试、统一回执及SHA清单。大结果可以分片并附重组校验器；不得只给截图/PASS摘要/本机绝对路径。执行输入先冻结，结束再验；结果不可覆盖原件，失败/超时/未启动都列出。可复用已经交付的未改大原件，只引用本包archives.json完整SHA与包内相对路径，不重复发送相同GB文件。

每项填写receipt_template.json，状态使用PASSED_SCOPE / FAILED / BLOCKED / NOT_RUN / ANALYZED；review_kind区分AUTHOR_SELF_REVIEW / INDEPENDENT_CROSS_REVIEW / MANAGEMENT_DECISION。指出你是工具作者、RTL作者还是交叉审阅者。不要把所有任务写一个overall PASS。

最低字段：任务ID、对应R编号、范围、输入版本/完整SHA、实际复用证据及理由、实际执行命令/cwd/工具路径/版本/SHA、起止时间（含时区，建议北京时间）、退出码、日志/原件相对路径和SHA、预期/实际、发现与剩余条件。未执行项exit=null而不是0；合成fixture标SYNTHETIC；复用历史测试注明ORIGINAL_RUN_REUSED及原run身份，不改原时间。

真实物理失败或发现工具缺陷都是有效交付，不需要修到PASS才回传。版本/路径/schema适配是工具工作，不能改原日志或给真实时序/资源错误容差。逐文件哈希验证不证明硬件已执行，板端必须另有实际会话证据。

回传后管理方做完整性检查、关键证据抽查、分项结论一致性及涉及预算/契约的裁定；已经有独立审验且无新差异的结果，不再常规全量重跑。发生冲突先定位最小复现实验，记录为何需要追加运行。

本次仅生成待用户转交包；没有向外部协作者发送消息，没有晋升生产或自动升版总说明。
