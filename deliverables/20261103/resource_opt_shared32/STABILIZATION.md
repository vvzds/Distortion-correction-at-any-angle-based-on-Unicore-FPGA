# 无画面标记的动态仿射稳定 v2

## 本次修改

上一版左上768×8像素的黑白闪动是写进HDMI的反馈标签。v2从像素数据路径中彻底移除标签，不用遮盖、裁掉或修改电脑预览来隐藏它；显示器和预览都接收同一干净的视频。旧客户端即使误发原bit16标记开关也不会产生标签。正常退出、异常退出的恢复配置也统一移除平滑开关。强制终止进程时来不及串口恢复，但新固件本身不会产生黑白标记。

用户实板复测确认：黑白线和黑白闪点均已消失；矫正运动非常流畅，停稳后没有抖动迹象。仍发现转动时物体偶发拉伸回弹，以下比例约束针对该问题；不能把上一版流畅度验收视为新比例约束的效果验收。

分步回正由几个环节共同造成：图像估计与串口控制共用一个线程、全局特征匹配时暂停发指令、等待命令激活以及低频离散矩阵更新。本版改为：

- 独立图像估计线程，只保留最新待处理画面，旧画面不堆队列；控制线程继续定时下发最新轨迹。
- 上位机使用极分解平滑旋转/伸缩，限制每秒边角移动速度；默认700像素/秒、0.08秒响应，发送上限30次/秒。
- FPGA把收到的矩阵当成目标，在每个生成帧边界向目标推进剩余距离的一半，直至定点收敛；没有新命令的帧也继续推进，整帧始终使用同一矩阵。手动/关闭配置立即精确生效。
- 估计结果过期或连续丢失时保持最后轨迹，避免持续追赶不可信目标；R/X/P会使旧线程结果失效。
- UART接收超时粒度从50ms缩短至5ms，减少短回复等待造成的额外停顿。

这是30fps视频下的逐帧变化，不能承诺高于视频帧率的视觉流畅度，也不能消除相机、整帧DDR缓存、显示器及采集卡的物理延迟。平滑程度与响应速度存在取舍。

## 闭环反馈的变化与边界

无像素标记版使用UART新命令21h读取最近发布帧实际使用的六个定点系数、发布帧号和模式。主机记录时间历史，按`--capture-delay`估计采集帧对应的矩阵。本机固定相机±3°自动变换试验估计偏移为0.065秒，44个样本的中位边角关联残差2.12像素；默认采用该值。它不是曝光到显示的端到端延迟，换采集卡或缓存设置后需重估。

与上一版逐帧标签相比，这个时间关联没有精确的采集帧ID。采集卡延迟变化、重复帧、缓存模式变化可能使关联有一帧或更多误差，并引入残差或振荡。它会拒绝缺失/过旧历史；实板重测必须覆盖慢速转动、停稳和快速转动，不把软件仿真当成闭环效果验收。不能使用最新下发矩阵直接乘延迟残差。

匹配仍以固定参考为基准，ORB双向匹配/RANSAC重获，LK前后向光流连续跟踪，定期回固定参考。目标矩阵`A_target=A_seen @ D`；D为参考显示坐标到当前显示坐标。所有几何矫正由FPGA执行，电脑只缩放预览以适应窗口。

滚转没有固定±45°角度限制，但需要足够场景纹理和重叠视野。默认1.15倍裁边不能保证大角度无黑边。俯仰是透视变化，六参数仿射只近似小角度、平面或远景；近景视差、遮挡和物体独立运动无法由一个仿射矩阵全部消除。合成±3°通过不代表实板±3°验收。

## 启动与快捷键

代码修改期间未访问设备；用户随后已确认硬件连接并授权完成优化后直接板测。以下入口会访问开发板、UART和采集卡。新程序要求`release/clean_smooth_manifest.json`对应固件，拒绝旧标记固件。

```powershell
cd D:\restart\fpga-undistort
python -m pip install -r requirements-board.txt
python tools/start_feedback_trial.py --port COM9
```

或双击`start_board_trial.cmd`。入口核验SHA256、器件PG2L100H，通过普通JTAG下载SRAM，再打开Hagibis预览；不写Flash。串口和采集卡会被独占。新位流已经下载后可直接`python host/board_trial.py --port COM9`。

| 按键 | 行为 |
|---|---|
| S / 空格 | 回到固定裁边基准，等待画面稳定后取参考，开始动态稳定；空格再次按下关闭 |
| X | 关闭动态补偿，恢复0°固定裁边标定图像 |
| R | 重新取参考，按下后短暂保持相机静止 |
| P | 冻结当前指令矩阵 |
| G | 切换Gamma，默认关闭 |
| + / - | 增减固定裁边；稳定中会重新取参考 |
| Q / Esc / 关闭窗口 | 退出并尝试恢复0°、1倍、无标记图像 |

快捷键仅在本窗口有焦点时有效。不要仅让重复棋盘格占满画面，应包含非重复静态纹理。默认不保存图片或视频，会话日志留在本机`reports/stabilization_runs`。

可调项：`--shape-limit .02`把相对参考裁边的每个主轴伸缩限制在约±2%（两个主轴比例最多约4.04%）；`--shape-limit 0`完全锁定伸缩与剪切，俯仰只剩旋转/平移近似。`--shape-response .8`单独控制比例的响应，`--shape-rate .015`限制对数伸缩每秒最多约1.5%，不拖慢滚转响应。`--response-time .08`越大越柔和、延迟越大；`--max-speed 700`限制回正速度；`--deadband .5`抑制目标估计噪声；`--capture-delay .065`必须结合实际采集链验证，不能靠增大发送频率代替。

- `tools/check_board_trial.py`：内存模拟，无任何设备；250ms没有新估计时控制仍继续发送、小幅推进；旧线程结果不能覆盖X，退出精确恢复。
- `sim/affine_smooth_tb.v`：逐帧推进、正负定点舍入、收敛、关闭后精确配置、遗留标签bit不会改变像素。
- `sim/host_control_tb.v`：原子配置、保留位、21h反馈字段和CRC。
- 两帧原生DDR整帧逐像素检查：旧标签bit开启→关闭，两个完整1920×1080画面均与无标签黄金模型一致。

旧`feedback_manifest.json`及其历史板测仍保留，不能用它们的实测结论证明v2已通过。v2已在本机下载到SRAM，静止闭环12秒约30.02个发布帧/秒，286次估计、0次拒绝，未出现核心/写入故障、patch越界或UART错误，正常退出恢复精确0°配置。小幅自动变换测得本机时间关联偏移约65ms；人工滚转/俯仰和退出闪点仍以复测反馈为准。新记录见`reports/clean_smooth_v2_summary.json`。

人工操作会话的前717秒快照记录了约30.000个发布帧/秒，716次健康查询均无核心/写入/越界/串口故障；8027次有效估计、991次拒绝。解码后的估计结果年龄中位31ms、95分位140ms，这不是相机到显示器延迟。拒绝或HOLD期间会暂停目标更新，仍可能有主观停顿，不能仅凭帧率验收平滑度。该文字快照见`reports/clean_smooth_v2_live_receipt.json`，不含摄像头图片；当前人工观感与退出闪点反馈尚未收到。

## 比例回弹修正（上位机更新，位流不变）

上一轮8762次有效观测中，重构目标的两个主轴缩放比最大约1.159，实际发布矩阵也达到约1.157；低残差并不能证明全幅比例正确，狭窄特征支持和近景视差可能让完整仿射出现形变。现对`A_seen @ D`重构后的绝对矩阵相对基准裁边作极分解，旋转和平移继续快速更新；对称对数伸缩单独限幅、限速、慢响应，并保留目标的画面中心位置。必须有至少25%包围范围、6/12网格、45个内点、65%内点率、2.5px以内RMS才允许更新形状；支持不足时保持已有形状。3‰的小比例噪声死区减少呼吸。不能直接约束延迟画面的残差矩阵，否则会把FPGA已作的补偿当成相机运动。

`tools/check_shape_stabilizer.py`覆盖噪声伸缩、全周滚转、中心位置保持、窄范围特征拒绝与持续小幅形变；不访问设备。默认更重视物体比例稳定，因此较大俯仰的比例补偿幅度会受限，六参数仿射的透视/视差边界依旧存在。用户人工复测确认：拉伸明显减少，仍然流畅。此反馈表示改善得到确认，不代表所有场景的形变已完全消除。

比例约束新版实板会话139秒快照：1456次有效估计、66次拒绝；原始拟合最大主轴比例1.0765，约束后目标最大1.0142，主轴相对缩放落在0.9873～1.0127；发布约29.998fps，未报核心/写入/越界/串口错误。该数据只说明约束已作用到实板控制，不能代替拉伸观感和俯仰回正的人工复测。见`reports/shape_stabilizer_live_receipt.json`。

本轮最终人工复测反馈：比例约束版“拉伸明显减少，仍然流畅”。保留默认参数；黑白闪线/闪点消失、停稳无抖动为前一轮已确认结果。近景视差及较大俯仰依旧受六参数仿射近似限制。

## 固定裁边黑角优化试验

独立入口`start_fixed_crop_trial.cmd`现用`--zoom 1.5`启动同一个板测程序；2.4倍为下述历史高裁边试验。固定裁边，不随旋转角度改变画面大小，位流仍为clean_smooth。备选一号独立目录、Git标签及桌面快捷方式保持1.15倍。S/X对比时均维持启动时的固定倍数；按加减键可手动改变倍数，但以下覆盖数据仅对应2.4倍。正常退出仍恢复1倍标定图像。

黑角是输出像素反投影超出摄像头已采集范围，双线性插值无法补回未拍摄的真实内容。当前真实Brown4标定下，1.15倍在全周滚转会越界；无额外平移/形变时2倍的360个整数角度周界采样最小余量约12.3源像素。试验选择2.4倍，为小幅俯仰等引起的中心偏移留余量；3456组采样覆盖每5°滚转、多个伸缩方向、每轴±90理想源像素中心偏移及约±2%主轴形变，最小周界余量5.42源像素；采样最差情形及四个直角方向均完成2073600点定点映射检查，无越界，取块保守边界通过。见`reports/fixed_crop_checks.json`与`tools/check_fixed_crop.py`。这是离线采样范围，不是任意连续姿态的保证，也不能把±90像素偏移等同于确定的俯仰角。

2.4倍与原1.15倍相比，理想图像平面的横纵显示范围约为47.9%，面积约23%；实际光学视角受Brown畸变影响，不直接等于这些比例。输出仍1920×1080，但放大会减少可见细节并降低观感锐度。大平移、透视、近景视差、跟踪丢失仍可能出现黑边。没有加入动态变焦或边缘复制填充。扩大传感器ROI/改变读取模式需重新标定与验证30fps链路，本次未改摄像头寄存器。

固定2.4倍实板首80秒遥测：发布约30.009fps，无核心/写入/越界取块/串口错误；曾出现无效映射像素，近邻矩阵中心偏移达约365理想源像素，明显超出离线±90像素范围。因此本次未宣称无黑边验收通过；继续固定裁边试验，用户画面反馈待补充。文字快照见`reports/fixed_crop_live_receipt.json`。

### 依据人工复测改为1.5倍折中

用户确认2.4倍“黑边减少，但裁切太多”，因此独立入口改为1.5倍，不改变备选一号。1.5倍相对1.15倍保留约76.7%的横纵理想平面范围、约58.8%的面积；比2.4倍视野明显更宽，放大软化更轻。真实标定周界定点采样中，无额外平移/形变时可连续覆盖约±22°整数滚转，1.4/1.6/1.7/1.8倍对应约±18/26/32/38°；这些不是包含俯仰、位移和标定误差的保证范围。大角度黑角为本次保留视野的明确取舍。运行中不会自动变焦；加减键可手动比较，S重新取参考。1.5倍实板复测后，用户确认“1.5倍较合适”，保留为当前固定裁边黑边优化方案；大角度及大位移仍可能出现黑角。
