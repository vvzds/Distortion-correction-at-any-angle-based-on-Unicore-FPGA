## §1 系统概述

### 1.1 功能定位与任务覆盖

本系统在 1080p HDMI 视频链路底座上实现**运行时图像畸变校正**：对 DDR 帧缓冲中的原始视频帧执行"反向畸变映射 + 双线性插值"生成校正帧写回 DDR，显示侧切换读校正槽输出；畸变参数（焦距、主点、径向/切向系数、仿射矩阵）与 Gamma 曲线经 UART 由上位机**运行时下发**，无需固化标定即可完成全部开发、验证与演示。

**选题二任务覆盖表**：

| 任务 | 内容 | 承担方 | 状态（V1.2 时点） |
|---|---|---|---|
| 基础任务一 | OV5640 采集 → DDR 帧缓冲 → HDMI 1080p 显示底座 | 一号协作者 | 已交付，C1'-C5' 接口冻结，板级阶段 1/2 验收 PASS |
| 基础任务二 | 畸变 8 参数 UART 下发（0x01）+ 反畸变映射引擎 | 我方（param_mgr ✓）+ 二号（undistort_core） | param_mgr 已交付仿真 PASS；core 阶段 1 方案已批准、RTL 进行中 |
| 高阶任务一 | 仿射变换（平移/缩放/小角度旋转，0x02 + aff_en） | 我方 + 二号 | 协议 V1.2 修订（G01），随 param_mgr 返工生效 |
| 高阶任务二 | 直方图统计与均衡 | 二期 | 预留（gamma_hist 模块名、UART 0x04 bit1） |
| 高阶任务三 | 三通道 Gamma 曲线校正（0x03/0x04 + gamma_lut） | 我方 | gamma_lut 已交付仿真 PASS |
| 演示配套 | 状态回读（0x05）、上位机参数下发脚本、标定图卡 | 我方 | 脚本暂缓（Python 环境就绪后）；图卡见 §6.3 |

### 1.2 总体架构与数据流

```
OV5640 ──► 采集 ──► DDR 原始槽 0–3                [一号底座：采集/帧缓冲/显示]
                              │
                              │ C1'-D2 源帧申请（hold_req/gnt/slot/rel）
                              │ C2' 行突发块读（960字=120拍，len=119）
                              ▼
UART ──► param_mgr ──► undistort_core ──► gamma_lut ──► rect_wr_if
（参数下发）  （我方✓）    （二号：反畸变映射  （我方✓：     （我方，待编码：
                          +双线性插值+行缓存）  Gamma映射）   像素对打包+顺序写）
                                                      │
                                                      │ C3'-D3 目标槽申请 + commit
                                                      │ C3' 整字写（32bit）
                                                      ▼
                          （校正子系统，单一 125MHz DDR 域）──► DDR 校正槽 4–7
                                                                     │
                                                                     │ C4' RD_SLOT_BASE=4
                                                                     ▼
                                                           HDMI 显示（1080p@30）[一号底座]
```

- 像素格式 **RGB565**（[15:11]R、[10:5]G、[4:0]B），全链路统一；
- 校正子系统全部驻留**单一 125 MHz `ddr_clk` 域**，无新增跨时钟域（契约 D5-5.2）；
- 三方分工：一号 = 底座与 C1'-C5' 链路侧实现；我方 = param_mgr / gamma_lut / rect_wr_if / 顶层集成 / 标定与上位机；二号 = undistort_core 主引擎。

### 1.3 设计约束与原则

1. **不动已验证模块**：旁路（`RD_SLOT_BASE=0`）时原始链路行为与基线位流一致；对一号底座仅通过 `correction_hook` 挂接，不改动其内部已验证逻辑；
2. **接口冻结纪律**：C1'-C5' 信号名/位宽/语义/时序已于 2026-10-14 冻结，任何变更须双方书面协商（差异表→确认书流程），单方面变更无效；
3. **功能正确优先于吞吐**：任意合法参数下输出正确性不受缓存策略牺牲——行缓存未命中先装载再输出，允许流水暂停；
4. **帧率三线分离承诺**：接口验收通过、采集 30fps 名义值、真实校正帧率三者分开验证与报告（§7.3）；
5. **工程语言与时钟域纪律**：Verilog-2001（禁 SystemVerilog 特性）、单时钟域、参数化用 `parameter`、中文注释、$display 文本用英文。

### 2.2 DDR 帧缓冲布局（契约 D1 冻结）

- **8 槽布局**：原始帧槽 0–3 + 校正帧槽 4–7；槽跨度 2^20 字，每帧 960 字/行 × 1080 行 = 1,036,800 字，8 槽共 32 MiB（器件容量前置检查通过；板级槽 4–7 别名验证已关闭，见 §2.4）；
- **字格式**：每 32bit 字打包 2 个 RGB565 像素，**偶数列 x 的像素在字低 16 位**；
- **地址公式（双方统一冻结）**：`Aword = slot × 2^20 + y_mem × 960 + floor(x/2)`；有效字地址 23 位，外部端口 24 位（bit23 须为 0）；
- **契约常数**（`video_contract.vh`）：`VC_SLOT_WORD_BITS=20`、`VC_ROW_WORDS=960`、`VC_FRAME_WORDS=1036800`；
- **C1 完成定义**：最后一行最后原生写突发结束链（`axi_wusero_last → wr_cmd_done → 行级 ddr_wdone → 1080 行计数 → 完成脉冲`），完成槽号与脉冲同拍锁存；部分帧不发布；完成脉冲后该槽读可见完整新帧（写后读可见性，板级 R2 已验证 PASS）。

### 2.3 底座挂接（correction_hook 与槽基址切换）

- 生产模式 4 下，`correction_hook.vh` 将 `corr_*` 契约信号直连至顶层（全程无寄存级）；
- **显示跟随（C4'）**：`RD_SLOT_BASE[2:0]` 为编译期 parameter（公共头 `VC_RD_SLOT_BASE`）：`3'd0` = 旁路（跟随原始四槽）、`3'd4` = 校正（跟随校正四槽）；两组槽内选帧机制完全同构——帧开始锁定最新完整帧、整帧槽号不变、防读写同槽保护沿用；
- **已批准实现差异**（冻结基线组成部分，我方消费者义务）：
  1. **写侧 64 字聚合**：链路缓存 64 字（8×256bit）再发原生写命令；要求整帧从槽基址逐字 +1 连续写、y_mem 升序，不支持乱序/掩码/取消——我方 rect_wr_if 为顺序流式写，天然兼容，无需适配改动（§4.4）；
  2. **无帧取消接口**：协议错误粘滞，中途失败须整体复位——我方以参数有效性门控（§3.5）预防，设计上不发生中途放弃；
  3. **目标槽申请安全等待**：前帧 commit 排空期间 `corr_wr_slot_req` 排队等待，消费者不假设等待上限、不做超时仲裁——"永不阻塞"结论修正为"排队最多 1 帧排空时长，不丢帧不阻塞显示"；
- **已知预期行为**：生产模式 4 + 空 hook = 黑屏（接入真实 core 后消除，非缺陷）；LED4 常亮为 CMOS1 空座、I2C 无外部上拉时配置流程误判完成的例程固有行为，不作验收判据。

## §3 畸变校正算法规格

### 3.1 坐标系与方向换算

- 两套行坐标：**内存行坐标 y_mem**（0–1079，帧缓冲写序，y_mem=0 行先写先出）与**屏幕行坐标 y_screen（v_s）**（0 = 画面顶行）；换算关系 `y_mem = 1079 − y_screen`；
- 契约接口地址一律采用 y_mem；标定参数基于屏幕方向图像（从上到下）由上位机计算；方向换算由校正侧（undistort_core）内部承担，链路侧与现有读序零改动；
- **输出行序（冻结）**：y_mem 升序（y_mem=0 行先出），与原始帧写同构——旁路与校正两种模式的显示屏幕方向自动一致，决赛对照演示无方向跳变；不采用"校正模式改变读序"方案。

### 3.2 反畸变映射总链（唯一正确性依据，实现须逐句对应）

```
遍历：输出行 y_mem = 0 → 1079（升序）；行内 u = 0 → 1919
对每个输出像素 (u, y_mem)：
  v_s = 1079 - y_mem                          // ① 输出屏幕行
  // ② 仿射（i_aff_en=1 时，屏幕域，Q16.16）
  // 【D02 修复式】乘积和与平移量分离：先右移再相加。
  //   （V1.1 原式把 Q16.16 平移量直接并入 Q32.32 乘积和属量纲错误，
  //    平移贡献仅剩 1/65536 像素；冻结修复式如下，golden 按同式独立实现）
  P_x = a11*u_q + a12*v_s_q                    // Q32.32 乘积和，累加器 ≥48bit 有符号
  x_p = (P_x >>> 16) + tx                      // u_q = u<<16 视作 Q16.16
  P_y = a21*u_q + a22*v_s_q
  y_p = (P_y >>> 16) + ty
  （aff_en=0 时 x_p=u_q, y_p=v_s_q）
  // ③ 归一化（帧首已算 inv_fx, inv_fy，见 §3.4）
  xn = ((x_p - cx) * inv_fx) >>> FRAC_INV      // 归一化坐标
  yn = ((y_p - cy) * inv_fy) >>> FRAC_INV
  // ④ 畸变正向模型（OpenCV 4 参数 + 二阶切向，无 k3）
  r2  = xn*xn + yn*yn
  xd  = xn*(1 + k1*r2 + k2*r2*r2) + 2*p1*xn*yn + p2*(r2 + 2*xn*xn)
  yd  = yn*(1 + k1*r2 + k2*r2*r2) + p1*(r2 + 2*yn*yn) + 2*p2*xn*yn
  // ⑤ 源坐标（屏幕域，Q16.16）
  sx  = fx*xd + cx
  sy  = fy*yd + cy
  // ⑥ 边界钳位（先钳位再取整，防行缓存越界）
  sx = clamp(sx, 0, 1919) ; sy = clamp(sy, 0, 1079)
  i = floor(sx) ; j = floor(sy)                // 像素整数坐标（屏幕域）
  wx = sx - i ; wy = sy - j                    // 插值权重 ∈ [0,1)
  // ⑦ 源邻域（屏幕行 j ↔ 内存行 rowA；屏幕行 j+1 在 j 下方 = mem 行号 −1）
  rowA = 1079 - j
  rowB = clamp(rowA - 1, 0, 1079)              // 【D04】屏幕底行 j=1079 时 rowB=0=rowA
  p00 = src[rowA][i]   p01 = src[rowA][i+1]
  p10 = src[rowB][i]   p11 = src[rowB][i+1]
  // ⑧ 双线性（R/G/B 拆通道，各自 5/6/5bit）
  out = (1-wy)*((1-wx)*p00 + wx*p01) + wy*((1-wx)*p10 + wx*p11)
  // ⑨ 行缓存供给：rowA/rowB 所在行未在缓存中则先发起行加载（§4.2）
```

**D02 修复式（冻结）**：

| 项 | 冻结式 |
|---|---|
| 乘积和 | `P = a·u_q + b·v_s_q`（Q32.32），累加器 ≥48bit 有符号 |
| 平移 | `x_p = (P >>> 16) + tx`（y_p 同构）——乘积和右移后再加平移量 |
| golden | 按同式独立实现（含截断顺序）；**严禁把 RTL 计算式直接翻译成 golden** |

**滑动方向与访问模式**：y_mem 升序 → v_s 降序 → 常规弱畸变下 sy 单调降 → j 从 ~1079 降到 0 → **mem 行号单调递增前进**，相邻输出行共享 1 个缓存行（"每输出行约 1 次行加载、最坏 2 次"）。预载逻辑按"下一输出行源 mem 行 ≥ 当前行"设计。

**【D01 注记】上式访问预算为弱畸变近似**：k1 较大时单输出行内 sy 随 u 非单调、源行跨度可达数十行（k1=−0.1、fx=1000 实例为 34 行）。行缓存未命中逻辑必须支持行内多次换行装载（功能正确优先于吞吐，允许流水暂停），吞吐影响在 T8 如实报告（§7.3）。

### 3.3 双线性插值与边界规则

- **钳位语义**：越界源坐标钳到最近边缘像素（图像边缘 1 像素拉伸条），保证任何读地址不越界（行缓存内 960 字全行可用）；**本架构无黑边通路**——越界侧期望为边缘拉伸而非黑边（T5 逐点校验）；
- **rowB 钳位显式规则（D04）**：`rowB = clamp(rowA − 1, 0, 1079)`；屏幕底行（j=1079 → rowA=0）时 rowB=0=rowA，双线性退化为行内插值，golden 按同规则实现；
- **行号换算安全**：一律经有符号中间量，任何 DDR 请求行号先过 [0,1079] 校验，**禁止负行号转无符号回绕**；
- **i+1 越界**：sx 钳到 1919.99… 时 i+1=1920，直接复用 i（i+1 越界取 i，即钳 1919）；
- **wx/wy 判零**：恒等参数（k/p 全零、aff 关闭或恒等）下必须精确直通（T1 判据）；8bit 以下权重截断天然满足，采用 >8bit 权重须自行保证；
- **恒等整型直通**确认为 T1 合法可选实现（条件：畸变系数全零 + aff 关闭/恒等），不替代一般路径精度验收（D05）。

### 3.4 定点化规格与精度判据

| 量 | 推荐格式 | 强制要求 |
|---|---|---|
| 像素坐标 u,v,x_p,y_p,sx,sy | Q16.16（32bit 容器） | 帧值 |
| inv_fx / inv_fy | ≥28bit 小数纯小数定点（Q0.28 起） | 帧首计算一次；**禁止用 Q16.16 存倒数**（fx~1000px 时相对误差约 1.5%，映射误差可达 30px） |
| xn, yn | Q5.11（16bit 有符号，±16） | 精度 ≤ 2^-10；G02 范围下 |xn|max = (1920−0)/128 = 15（fx=128、cx=0 极值），Q7.24 候选容器 ±16 恰好贴边——须定点模拟复核该极值不溢出，必要时升 Q8.24（实现自由度，接口不变） |
| r2 | Q10.22 或等宽 | — |
| wx, wy | Q.8 | — |
| 插值累加 | 每通道部分积 ≤14bit，和 16bit，>>8 舍入（+0.5） | — |

- **精度验收判据（唯一依据，D05 口径）**：T3/T4 vs 独立 real golden——**每通道 max ≤ 2 LSB 且 ≤1 LSB 占比 ≥ 99.5%**；判据以最终源坐标绝对误差（px）+ 插值输出误差（LSB/通道）为准，零附近不单列相对误差规则；上表"推荐格式"为**非验收依据**；
- Q5.11 归一化量化在 fx≈1000、强畸变下可造成约 0.24px 源坐标误差（例：−0.34 量化为 −0.33984375，误差 0.156px），方案阶段须实测评估，不满足判据则加宽小数位；
- 精度推导参考：inv 相对误差 < 2^-23 保证 δxn < 2^-12（|x_p−cx| ≤ 2000px）；全链定点误差折合输出坐标 < 0.02px（不含归一化量化损失，见上条）；
- 定点模拟须覆盖边界值组合：fx=128、cx=0 / cy=0、k1=−0.5、tx=±4096 同帧组合。

### 4.1 param_mgr（UART 参数管理，我方，已交付 + V1.2 返工）

**行缓存（D01 口径）**：

- 参数 `LINES_PER_SET` 默认 2：乒乓双套 × 每套 2 源行 × 960 字 ≈ 15 KiB；
- 逻辑标签查找**不预设**"每输出行固定一对源行"；缺行替换策略：锁已命中行、选未锁定牺牲行、last 核对后置有效；
- 未命中先装载再输出，允许流水暂停（功能正确优先于吞吐）；
- 行缓存写入端每个 vld 沿整拍落地（120 拍全速接收）——"返回无回压"的消费者兜底义务在我方（§5.1 C2'）；
- 扩展预算：每 +2 行约 +3~4 DRM，≤12 DRM 预算下上限约 8 行；是否升 LINES_PER_SET=3 待 PDS 综合实测后由设计方裁定。

**参数采样（D06）**：帧启动 start 当拍复制全部参数入内部寄存器，帧中不重读；fx/fy ≤ 0 或超 G02 上界 → 兜底拒绝启动（保持 IDLE，计错可观测）。

**吞吐预算（契约 §4.4 口径）**：稳态 ≤ 2 拍/输出像素（含行切换气泡摊销），全帧 2,073,600 像素 × 2 ≈ 4.147M 拍 ≈ 33.2 ms @125MHz；行处理预算 3840 拍/行（30.7 μs），行加载 120 拍 + 读延迟 ≤ 64 拍被双套乒乓完全隐藏——**帧率瓶颈是 2 拍/像素的计算流水，不是 DDR**；行首允许多周期流水填充；帧首 inv 计算允许几十周期（迭代除法器，禁组合除法）。

### 4.3 gamma_lut（三通道 Gamma 映射，我方，已交付）

- 位置：undistort_core 校正像素流 → rect_wr_if 之间（125 MHz 域）；
- `i_gamma_en=1` 时按 3×256 点 LUT 对 RGB565 像素逐通道映射；`i_gamma_en=0` 时像素原样旁路（bypass 对照演示）；
- LUT 数据不存本模块，直接索引 param_mgr 输出的 6144bit 扁平总线（避免双份约 12k FF）；布局 R=[2047:0]、G=[4095:2048]、B=[6143:4096]，每通道 256×8bit；
- 索引扩位 5/6bit→8bit 高位复制（R/B 补 3 位 `{c, c[MSB:MSB-2]}`，G 补 2 位 `{c, c[MSB:MSB-1]}`）；恒等 LUT 时经 8→5/6 截断**无损往返**（数学性质，独立可验，已纳入 TB 性质测试）；
- 严格 1 拍流水延迟，vld 透传；LUT/使能由 param_mgr 帧间隙原子切换，逐拍采样无需额外同步；
- 直方图统计与 CDF 均衡二期（模块名 gamma_hist 预留）。

### 4.4 rect_wr_if（校正写回，我方，待编码）

**职责**：

1. **D3 目标槽申请**：`corr_wr_slot_req` 电平保持到 gnt，gnt 拍锁 `corr_wr_slot`（4–7），保持到该帧 commit；
2. **像素对打包**：RGB565 像素流按"偶 x 在字低 16 位"打包 32bit 字；
3. **顺序流式写**：undistort_core 输出行序 y_mem 升序、行内 x 升序 → 写地址简化为槽基址起顺序计数，**天然兼容链路 64 字聚合**（整帧从槽基址逐字 +1 连续写，不乱序/不掩码/不取消，我方保证）；
4. **commit**：该帧最后一个写请求被 gnt 后立即发出 `corr_wr_commit` 单周期脉冲，随后即可申请下一帧源帧（D2 与 D3 生命周期相互独立）；链路排空后发布、显示帧边界切换（链路侧行为，commit ≠ 发布）。

**排队语义（安全等待）**：前帧 commit 排空期间 req 保持等待，不假设等待上限、不做超时仲裁——排队最多 1 帧排空时长，不丢帧不阻塞显示。

## §5 接口规格

### 5.1 C1'-C5' 契约接口（2026-10-14 冻结）

**C1' 原始帧状态可见**：

| 信号 | 方向（链路视角） | 位宽 | 语义 |
|---|---|---|---|
| `o_frame_wcnt` | 输出 | 2 | 最新完成原始帧槽号（0–3，不保证交替） |
| `o_frame_update` | 输出 | 1 | 单周期完成脉冲，与槽号同拍锁存 |

完成定义 = 最后一行写结束链（§2.2）；部分帧不发布。

**C1'-D2 源帧保护**：

| 信号 | 方向 | 位宽 | 语义 |
|---|---|---|---|
| `corr_src_hold_req` | 校正→链路 | 1 | 源帧锁定申请（电平，保持到 gnt） |
| `corr_src_hold_gnt` | 链路→校正 | 1 | 受理（电平，gnt 后保持到 rel） |
| `corr_src_slot` | 链路→校正 | 2 | 被锁定源帧槽号，gnt 拍起有效 |
| `corr_src_rel` | 校正→链路 | 1 | 释放（单周期脉冲） |

协议规则：gnt 锁定当时**最新完整原始帧**（req 悬挂期间新帧完成则锁新帧，后到优先）；最大同时持有 1 帧；被锁槽 rel 前不得分配给采集写；**rel 前提** = 该帧全部块读数据返回并消费完毕 + 引擎流水排空 + 最后校正像素已输出；处理期间新完成帧跳过属正常行为（非错误）。

**C2' 行突发块读（B2 级）**：

| 信号 | 方向 | 位宽 | 语义 |
|---|---|---|---|
| `corr_rd_req` | 校正→链路 | 1 | 块读请求有效 |
| `corr_rd_addr` | 校正→链路 | 24 | 起始字地址（行首：slot×2^20 + y_mem×960，960 字 = 整 120 拍，天然 256bit 对齐） |
| `corr_rd_len` | 校正→链路 | 7 | 拍数 − 1（行加载恒 119；支持 1–128 可变） |
| `corr_rd_gnt` | 链路→校正 | 1 | 受理 |
| `corr_rd_vld` | 链路→校正 | 1 | 返回数据有效（连续流，无回压） |
| `corr_rd_data` | 链路→校正 | 256 | 数据拍 |
| `corr_rd_last` | 链路→校正 | 1 | 末拍标识（对齐原生 axi_rlast 语义） |

> **C2' 冻结时序注记（接口冻结确认书 §3/§6，消费者可依赖的保证）**：
> 1. `corr_rd_gnt` 为 **ready 电平**（桥空闲且地址合法时置起，可先于 req 存在；源码事实 `corr_rd_gnt = rst_n && !corr_busy && address_ok`，组合逻辑经 hook 直连无寄存级）；
> 2. **受理 = req && gnt 同拍**，受理前 addr/len 稳定；
> 3. **受理拍无数据返回**（无零周期返回）：首 vld 最早晚于受理拍 1 拍；简化模型实测 gnt→首 vld 最大 9（六行并发）/ 27（带停顿）/ 32（完整 1080p）周期，满足 ≤64 目标，实物以上板实测为准（R4）；
> 4. **单在途**：块占用期间 gnt=0，至 last 不受理第二块；完成拍后最早下一拍可再受理（1 拍气泡正常）；
> 5. 返回流**允许间隙**（真实 rvalid 路由），last 只在逻辑块末拍；Column 拆分中间 rlast 不作逻辑 last；
> 6. 返回**无回压**：行缓存 1 拍/周期全速接收义务在校正侧（消费者兜底），链路侧无需提供任何缓冲。

数据拍→像素映射（TB 理想 DDR 按同一定义生成数据）：第 p 拍（p=0..119）含 8 个字：字 w = 8p+j（j=0..7），`word_j = data[32*j+31 -: 32]`；字 w 含像素对（x=2w 在低 16 位，x=2w+1 在高 16 位）。仲裁：共享读通道内**显示读优先、校正块读次之**（校正侧行缓存有 ≥30 μs 级裕量可等）。

| `corr_wr_req` | 校正→链路 | 1 | 写请求有效 |
| `corr_wr_addr` | 校正→链路 | 24 | 目标字地址 |

### 5.3 UART 参数协议（V1.2 修订版）

**物理层**：115200-8-N-1；**payload 字节序：小端**（低字节先发，模块内以 `{b[3],b[2],b[1],b[0]}` 形式拼装）；**帧校验**：checksum = payload 累加和低 8 位（len=0 命令 checksum 为 0x00）。

**帧格式**：`AA 55 | cmd | len | payload(len B) | checksum`；坏帧（帧头错/校验错/长度错）整体丢弃，从下一字节重新找帧头；连续 0xAA 按帧头保持处理。

**命令表**：

| cmd | len | payload | 功能 | 任务归属 | 版本 |
|---|---|---|---|---|---|
| 0x01 | 32 | fx, fy, cx, cy, k1, k2, p1, p2（小端 Q16.16 依次拼位） | 畸变 8 参数下发 | 基础任务二 | V1.0 |
| 0x02 | **25** | a11, a12, a21, a22, tx, ty（24B 小端 Q16.16）+ **第 25 字节使能：bit0=aff_en，bit7..1 保留写 0** | 仿射 6 参数 + separate 使能下发 | 高阶任务一 | **V1.2 修订（G01）** |
| 0x03 | **通道号 0/1/2** | 该通道 Gamma LUT 固定 256 字节（0=R、1=G、2=B；>2 丢帧） | Gamma 曲线分 3 帧下发 | 高阶任务三 | **V1.2 修订** |
| 0x04 | 4 | 模式位（小端 32bit 字）：bit0=gamma_en，bit1=直方图均衡（二期），其余保留 | 模式控制 | — | V1.0 |
| 0x05 | 0 | —（回读请求） | FPGA 回发 `AA 55 05 04 status[4B 小端] checksum` | 演示配套 | V1.0 |

**0x02 修订式（G01 裁定）**：

| 项 | V1.1 现状 | V1.2 修订式 |
|---|---|---|
| payload 长度 | 24 字节（a11..ty 6 参数 × 4 字节） | **25 字节**（a11..ty 不变 24 字节 + 尾部专用使能字节） |
| 使能字节 | 无（复用字节 0 bit7——与 a11 最低字节协议层互斥：aff_en=1 要求该字节 bit7=1（≥0x80），而恒等系数 a11=0x00010000 要求该字节=0x00，二者不可兼得，T5 纯平移仿射无法经 UART 下发） | **第 25 字节**（payload 下标 24）：bit0=aff_en，bit7..1 保留写 0（读侧忽略） |
| 字节序 | 小端字节序（低字节先发），a11={pay_buf[3..0]} 拼装 | **不变**（仅 sh_aff_en 改源 `pay_buf[24][0]`） |
| len 字段 | 24 | **25** |
| 原子性 | 帧间隙统一切换 | **不变**（使能与系数同帧同拍进影子寄存器） |

不采用的备选（均已否决）：接受 a11 偏差（LSB ≥ 0x80 即恒等基点上浮至 a11 ≥ 1.001953，u=1920 时缩放偏差约 3.7 像素，T5 纯平移判据失效）；aff_en 独立 0x04 命令（与 0x02 分帧破坏参数集原子切换）。

**0x03 分帧修订**：V1.1 原定 len=768 超出单字节长度上限 255、无法表达；修订为分 3 帧按通道下发——len 字段复用为通道号（0=R/1=G/2=B，其他值丢帧），payload 固定 256 字节该通道 LUT；三帧独立下发、独立校验，任一帧生效即更新对应通道。

**TX_GAP（0x05 回发时序，冻结要求）**：DUT 收完 checksum 当拍即回发会导致起始沿早于上位机"发送→接收切换"完成，接收端错过起始沿、锁到数据流内伪下降沿、每字节错位 1 位。**回发帧起始位必须晚于下行帧结束 ≥ 2bit**（param_mgr 实现 `TX_GAP_CYC = 2*DIV`，组装完成后先停顿再发起始位）。

**原子切换与 params_valid**：参数帧解析完成写入影子寄存器；仅当 `i_rect_busy==0` 帧间隙原子切换到生效组（同帧同拍，参数集无撕裂）；`o_params_valid` 复位默认 0，完整合法参数组（含 G02 范围校验）首次生效后置 1（D06，与 core 兜底校验双保险）。

**上位机脚本**：Python 参数下发/状态回读脚本暂缓（环境就绪后随 param_mgr 返工一并交付），协议以本节为准。

## §6 验证计划

### 6.1 仿真验证

**TB 三理想模型**：

1. **ideal_granter（D2 服务端）**：可配 gnt 延迟 0–16 拍；TB 在随机时刻产生"新帧完成事件 + 槽号"，校验"req 悬挂时新帧完成 → gnt 锁最新"与"hold 期间新帧被跳过"；
2. **ideal_ddr（C2' 服务端）**：可配 gnt 置起延迟 0–8 拍（真实链路 gnt 为 ready 电平、通常已预先置起）；受理后延迟 D∈{1,16,64} 拍起**连续 120 拍 vld**（真实链路冻结保证 D≥1；D=0 零周期返回在真实链路不存在，为可选健壮性项）；数据按字-像素映射公式（§5.1）从 TB 源图数组生成；内置协议断言（在途>1、addr 非行首对齐、len≠119 等违规计数）；
3. **golden 参考模型**：`real` 全精度独立实现 §3.2 全链公式 + 钳位 + 双线性。**严禁把 RTL 计算式直接翻译成 golden**（RTL 与 golden 同源共错时一致性测试会全过）；T1/T2 全帧精确比对（直查源图数组），T3-T5 网格抽查（如全帧 1/16 采样点）控制仿真时长，T1/T2 必须全帧。

**用例与判据（T0-T9）**：

| # | 用例 | 参数 | 判据 |
|---|---|---|---|
| T0 | 复位 | — | busy=0，无任何请求/输出 |
| T1 | **恒等无损（性质测试）** | k1=k2=p1=p2=0，aff_en=0，fx/fy/cx/cy 任意合法值 | 输出**逐像素精确等于**源图（零畸变下 fx/fy/cx/cy 在公式中自相抵消——映射+插值全路径无损检验） |

| T3 | 径向畸变（强） | §3.5 冻结表 | vs golden：每通道 max ≤ 2 LSB，且 ≤1 LSB 像素占比 ≥ 99.5% |

| T5 | 平移仿射三组（D08 扩展） | tx=+40.0、tx=−40.0、tx=+40.5（均 Q16.16），aff_en=1，非对称图案 | 中心区 vs golden 同 T3；逐像素核对源坐标（tx 语义冻结：反向采样 src_x = out_x + tx，tx=+40 内容左移、右侧越界）；越界侧 40px 边缘带逐点校验钳位拉伸语义（非黑边） |

- **param_mgr_tb**：帧头/长度/校验/通道号各坏帧丢弃、0x01-0x05 正常向量、原子切换时序（busy 滞留影子、帧间隙生效）、TX_GAP 采样（UART 接收 task 等起始沿后须等 1.5bit 到 data0 中心）、V1.2 返工后 0x02 尾使能字节向量与全命令位复用自查；
- **gamma_lut_tb**：恒等 LUT 无损往返（性质测试，独立于一致性测试抓公式错误）、旁路直通、1 拍流水、三通道索引扩位正确性（5bit→8bit 补 3 位、6bit→8bit 补 2 位）。

**PASS 判据与证据**：每用例一行 `[Tn] PASS/FAIL (err=k)`；全过打印 `=== ALL TESTS PASSED (err=0) ===`；watchdog 独立 initial 块（建议 60ms 仿真时上限）；证据 = vsim 控制台全文（含统计端口终值）随 commit 回传。

**编码约束与已知坑（前人实测教训，直接继承）**：Verilog-2001 only（数组元素先取字到普通向量再切片，`arr[i][7:3]` 为 SV 特性）；TB `@(posedge clk)` 后加 `#1` 跨过 NBA 区再比对；UART 接收 task 等起始沿后须等 1.5bit（DIV+DIV/2）到 data0 中心；位复制扩位只补差额位（5bit→8bit 补 3 位、6bit→8bit 补 2 位）；帧首 2 次除法用迭代除法器（约 40 周期），禁推断组合除法；切换脉冲"在发送函数返回前已发完"的等待竞态用计数增量检测而非电平等待；中文注释、$display 英文；每模块一文件，参数化用 parameter。

### 6.2 SIM_MODE 与统计口径（D07 冻结）

- **SIM_MODE=1**：跳过映射/插值计算，按契约滑动访问模式（每输出行 1–2 源行、相邻输出行共享缓存——**该模式为契约约定的压测负载，属弱畸变近似，不代表强畸变真实序列**）生成真实命令序列与统计，供一号压测 C2' 读通道；此模式不输出有效像素流、**不宣称发布完整校正帧**；
- **完成条件** = 全部输出位置访问分析完成 + 最后块返回 + 流水排空，完成即停；
- **统计口径（行级粒度，杜绝按像素/按行混比）**：
  - `o_stat_pix_cnt` = 本帧输出像素（像素流 vld 拍计数，帧启动清零）；
  - `o_stat_line_loads` = 本帧发起且被受理的逻辑行加载数（含同帧重复装载；链路 Column 拆分对 core 不可见、不重复计数）；
  - `o_stat_line_hits` = 零行加载完成的输出行数（**每输出行一次判定，帧总查询数恒 1080**）；
  - 本帧活动计数在下一次成功启动新帧时清零；末帧结果由顶层锁存快照供帧间读取（快照机制联调时约定）。

## §7 资源与性能预算

### 7.1 DDR 带宽预算（256bit 拍/秒，125 MHz 域，30fps 名义口径）

| 数据流 | 计算 | 拍/秒 | 占总线 |
|---|---|---|---|
| 原始帧写 | 30fps × 1080 行 × 120 拍 | 3.888 M | 3.1% |
| 显示读 | 30fps × 1080 行 × 120 拍 | 3.888 M | 3.1% |
| 校正行加载（最坏：每输出行 2 行全加载） | 30fps × 1080 × 240 拍 | 7.776 M | 6.2% |
| 校正帧写 | 30fps × 1080 行 × 120 拍 | 3.888 M | 3.1% |
| **合计（未计刷新/命令开销）** | | **≈ 19.4 M** | **≈ 15.6%** |

按 DDR 控制器效率 70% 保守估计仍有约 3 倍裕量。注记：上表"每行 2 次全加载"为契约保守上界；真实访问以二号阶段 2 RTL 轨迹统计为准——弱畸变 T1 每行约 1 次加载；T4 实例 22,279 加载/帧 ≈ 2.67M 拍纯读，上界假设成立；强畸变 T3/T6 超出 30fps 口径（§7.3）。

### 7.2 资源预算

| 项 | 预算/估算 | 说明 |
|---|---|---|
| 行缓存 | 乒乓双套 × 2 行 × 960 字 ≈ 15 KiB ≤ **12 DRM** | 当前工程 DRM 用量 11.5/155，充裕；每 +2 行 ≈ +3~4 DRM，12 DRM 预算上限约 8 行 |
| LUT 扁平总线 | `o_gamma_lut` 6144bit 扁平寄存 ≈ 12k FF | gamma_lut 不复制存 LUT（直接索引 param_mgr 输出总线），FF 代价在预算内 |
| 乘法器 | 映射流水定点乘法（映射 + 插值），推断乘法器 | 综合后以实测资源回填 |
| 除法器 | 帧首 2 次 inv 计算，迭代除法器约 40 周期 | 禁组合除法 |

### 7.3 帧率预算与三线分离口径

**三线分离（冻结承诺口径）**：

1. **接口验收**：C2' 环回自测 + 预算内吞吐/延迟实测（gnt→首 vld ≤ 64 周期等，§5.1）——与帧率无关，单独验证；
2. **采集 30fps 名义值**：底座采集链路口径（PCLK 84MHz / HTS=2500 / VTS=1120），与校正无关；
3. **真实校正帧率**：集成联调独立实测并如实报告；显示侧恒 30fps（帧缓冲补帧），校正帧率不足时跳帧、显示跟随最新完成校正帧，演示流畅性不受影响。

**校正引擎计算预算**：2 拍/输出像素 × 2,073,600 像素 ≈ 4.147M 周期 ≈ 33.2 ms @125MHz（与 33.3ms 帧周期相当）；叠加行切换气泡与读等待后，弱畸变场景预计 25–29fps。

**强畸变口径（D01，V1.2 定稿）**：k1=−0.1、fx=1000 量级下软件理想模型全帧访问估算——T3 纯读有效拍 6.03M（48.2ms @125MHz）、T6 10.34M（82.7ms）均超 33.3ms 帧周期，**默认四行缓存不可达 30fps**。处置：

- 按契约 §4.4 第 3 条"帧率按实测报告、不纳入 30fps 承诺"，**非 blocker**；
- 表中数据为**上界估算**（软件四路 LRU 比真实乒乓灵活、未计仲裁与间隙），真实轨迹以二号阶段 2 RTL TB 统计为准；
- `LINES_PER_SET` 维持默认 2，升 3 待 PDS 综合 DRM 实测后裁定（§4.2）；T4 场景（22,279 加载/帧 ≈ 21.4ms 纯读，叠加计算后约 25fps）预算内可用；
- **大角度画面旋转仿射**（破坏行局部性的极端场景）：功能可用、画面正确，帧率按实测报告（可能显著低于 30fps），不纳入承诺口径；畸变校正 ± 平移/小角度仿射（行局部性保持的所有场景）在预算内。
