## 冻结连接与验收边界

以下仅整理现有冻结接口，不改变信号或增加新的外部端口。所有校正相关 RTL 使用同一个 125 MHz DDR 时钟域。

1. `param_mgr` 的合法、完整参数帧在帧间隙生效；`o_params_valid` 门控 `i_frame_start`。`undistort_core.o_frame_busy` 接 `param_mgr.i_rect_busy`。core 帧首锁存参数，并二次校验。上电不能以复位零焦距启动。
2. core D2 `o_corr_src_hold_req` / `i_corr_src_hold_gnt` / `i_corr_src_slot[1:0]` / `o_corr_src_rel` 接一号源帧锁定器；源槽只能为 0–3。rel 表示源帧读完，与目标校正槽发布无关。
3. core C2′ `o_corr_rd_req/addr[23:0]/len[6:0]` 与 `i_corr_rd_gnt/vld/data[255:0]/last` 接一号行突发读桥。gnt 是可预先为高的 ready；仅 req&&gnt 同沿受理；受理拍无 vld；行读 len=119，读桥返回不支持回压。地址为 `source_slot*2^20+y_mem*960`，一个块 120 个 256bit 数据拍。
4. core `o_pix_vld/o_pix[15:0]/o_sop/o_eop/o_sof/o_eof` 送 `rect_wr_if`，经目标槽申请与顺序写回链到槽 4–7。校正写接口 32bit 字依地址 +1 连续写；偶 x 占低 16bit。最后一个写请求被受理后才 commit，链路排空后才发布；显示只在帧边界切校正槽。
5. 校正显示配置 `RD_SLOT_BASE=3'd4`；旁路回归配置 `3'd0`。两配置必须分别验证，不能把旧工程直接改参数 4 后出现黑屏判为 core 缺陷：空 `correction_hook.vh` 在模式 4 下本来就没有校正帧。

源：`verification/reference_package/02_contract/接口冻结确认书_C1C5回复.md`、`verification/reference_package/02_contract/contract_D1-D5_reply.md`、`verification/reference_package/00_TASK_BRIEF_undistort_core_v1.1.md`（路径均相对于 `work/undistort_core_v11`）。G4 不改变上述外部协议。

## 集成真正可执行的前置交付

1. 一号侧提供**当前冻结 C1′–C5′ 完整可编译 PDS 工程**（源码、IP 生成件或可重建配置、`.pds`、时钟/IO 约束、仿真模型与参考日志），并给出版本提交和 SHA256。只给旧 HDMI 工程或位流不够。
2. 设计方提供 `rect_wr_if`、顶层调度、UART→`param_mgr` 接线、参数合法门控与同版本验收脚本；确认修订 `param_mgr.v` 与原始参考件的取舍。缺少它们无法形成真实校正帧写回链。
3. 冻结 G4 四件 RTL 的同一源码哈希，先完成 G4 自校验和冻结 suite。集成线仅复制已验证版本，不将正在修改的工作树当生产快照。
4. 在能编译最小 FF probe 的 SP6.4 环境中，先完成顶层 elaboration、I0–I7 全真件用例，再执行完整 device_map、P&R、setup/hold 与约束覆盖检查。仅 core synth 的 WNS 或本机 SP6.1 失败均不能代替真实顶层物理结论。

## I0–I7 验收建议记录

收到设计方正式 I0–I7 定义后以其原定义为准，不在这里臆造编号。联调至少记录：两种 `RD_SLOT_BASE` 配置、源槽锁定期间不重分配、读请求受理/返回、帧首参数原子生效、RGB565 全帧像素顺序与行标记、目标槽顺序写及 commit→排空→发布、显示帧边界切换、复位/连续帧。独立 ModelSim TB 的通过不能推导 FPGA 真实 DDR 带宽、HDMI 时序或 125MHz P&R 闭合。

## 本轮未执行

缺少真实顶层、写回模块及正常可用的 SP6.4，故未运行全真件联仿、I0–I7、device_map 或 P&R，也未生成集成位流。历史 G3 core 综合 WNS -1.372ns、DRM 16，以及强畸变吞吐缺口仍维持原状态。
