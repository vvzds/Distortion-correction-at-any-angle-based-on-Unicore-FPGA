# G4读地址拆级方案（待设计方决策，2026-10-18）

**状态：仅方案，未修改RTL、未执行仿真/综合。** 基线为G3提交3e50aae及设计方SP6.4实测。启动依据须由设计方确定，见其G3接收结论§8.3。该文档提供具体可评审方案，不是新接口契约或已完成实现。

## 1. 首选最小范围

只修改 `source/rtl/undistort_core.v`；G3 map、line_cache、bilinear及全部既有测试/参考件不改。新增G4专用TB/runner与证据，现有冻结测试原样执行。

复用已有11位 `load_row` 和8位 `load_bank`，新增一个内部状态 `READ_ADDR=4'd11`，保留原状态编码。4位state已有空间，方案不需要增加新的地址流水寄存器或RAM；实际FF/LUT/APM映射仍须综合，不把源码计数当资源报告。

```text
当前：FIFO读 → 行号换算 → 命中判断 → 缺失行选择 → *960 + slot_base → addr寄存
方案：FIFO读 → 行号换算 → 命中判断 → 缺失行选择 → load_row寄存
                                                    ↓ 下一周期READ_ADDR
                                              *960 + slot_base → addr寄存/req
```

目标是切断命中选择与地址乘加的串接，不重写缓存替换算法，不同时压缩DRM。不承诺改善1.372ns或一次达到125MHz；其他路径可能成为新瓶颈。

## 2. 状态与请求时序

三处入口统一：RUN普通缺失行、RUN恒等预取、SIM_RUN缺失行。

|阶段|动作|外部req/受理|
|---|---|---|
|选择沿C0|锁存load_row/load_bank/read_return_state；设置prefetch_active；进入READ_ADDR|req保持0；即使gnt预先为1也不能受理、不能load_begin、不能计加载|
|地址沿C1|仅从锁存load_row/source_slot计算并寄存addr，len置119；拉起req并进入READ_REQ|addr与req同沿更新，更新后的首个有效req对应正确新addr|
|请求等待|READ_REQ保持addr/len/req，直到req&&gnt受理|单在途；缓存load_begin、加载计数和replace_cursor仅在受理沿更新|
|返回等待|READ_WAIT按原逻辑全速接收120个有效256bit拍，最后拍完成后回原状态|返回无回压；gnt→首数据仍按原冻结契约，不另插返回寄存|

地址表达式语义保持24位：

```verilog
// 仅示意READ_ADDR内地址生成，不是已应用补丁。
o_corr_rd_addr <= ({22'd0,source_slot} << 20) +
                  {13'd0,load_row} * 24'd960;
o_corr_rd_len <= 7'd119;
o_corr_rd_req <= 1'b1;
state <= READ_REQ;
```

不得仅给地址增加一拍却仍在C0拉起req，否则gnt提前为高时可受理旧地址。等待中不得重新用变化的FIFO头、query或consume_y计算请求；地址唯一来源为本次已锁存load_row/source_slot。

行0/1/1079的源槽内字地址分别0/960/1,035,840，均加 `source_slot*2^20`；len119对应120拍×8个32位字=960字。所有端口、位宽、地址单位及槽范围不变。

## 3. 预取与坐标流水对齐

- `map_issue`允许状态需包含READ_ADDR，维持原FIFO+在途<16规则，不在新状态无故暂停映射。
- 当prefetch_active=1时，`sample_dispatch`允许状态需包含READ_ADDR；仍受原sample_phase、fifo_count、hit_a/hit_b条件约束。普通miss/SIM不会因此放行缺失像素。
- load_row/load_bank在C0固定；预取时FIFO头可继续推进，C1地址不能跟着头部变化。替换保护仍使用C0确定的目标bank，不把地址周期改成第二次重新选victim。
- 初始化、帧参数快照、复位、源槽锁定/释放、输出标记及统计口语义不改。新增状态必须纳入复位/帧间清理与生命周期检查。
- req等待期间预取可能跨输出行边界，加载计数、current_line_loaded清除/置位及行命中统计必须按冻结语义验证，不能先承诺所有DDR调度条件下统计与G3逐拍相同。

## 4. 周期与吞吐影响

每次行加载在发req前增加一个内部地址准备周期；首返回延迟从实际req&&gnt受理沿起算，契约不变。

恒等预取大部分新增周期可被当前行像素输出隐藏，是否仍稳态≤2.0001拍/像素必须由原T1测试判定。普通miss可能逐次增加停顿，SIM_MODE也会延长；不能套用G1–G3“每帧只多1拍”的结论。强畸变loads/reloads很多，G4周期必须重新实测，不能把时序改善当吞吐问题已修复。

不修改冻结超时、golden、误差阈值或吞吐断言以制造PASS。若有真实失败，记录参数/请求序列/周期及原因，按失败处理。

## 6. 设计方决策项及后续边界

建议批准的具体范围是：**只在core内复用load_row增加READ_ADDR阶段，map/cache/bilinear、冻结外接口、现有验收判据均保留；增加G4新TB并执行完整原回归。** 若设计方选择先做真实corr_top P&R，本方案可保留为候选，不将RTL先行混入G3基线。

G4实施后仍需新的综合报告才能判断目标链是否切开，最终setup/hold终裁在真实corr_top P&R。DRM≤12、强畸变吞吐预算、上位机E1–E6修订属于另列事项，本方案不预设已解决，也不改变责任分工。
