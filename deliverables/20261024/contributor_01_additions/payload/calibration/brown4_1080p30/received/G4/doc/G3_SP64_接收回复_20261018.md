## 关键路径定位与措辞澄清

SNR L203–272最差路径：

```text
core.fifo_rd[2]寄存器
  → core.coord_y分布式RAM异步读
  → core.head_y / 1079-y换算
  → query_a
  → u_cache标签比较 / hit_a
  → core缺失行选择
  → N634 APM
  → core.o_corr_rd_addr[21]寄存器
```

另两条同链汇入地址[22]/[20]，slack分别−1.342/−1.142。最差路径logic3.351ns、route5.835ns，布线占63.521%。原G2 map内cx减法→乘法链已退出所列最差路径，与设计方拆级裁定一致；这不等于整个map所有路径已独立证明125MHz通过。

源码归属需精确：`coord_y`、`fifo_rd`、`head_y`定义于 `undistort_core.v`，不是line_cache内的“行头FIFO”；`u_cache`在这条链上提供组合标签比较与命中信号。`o_corr_rd_addr`同样由core生成。故G4首选可仅修改core调度，**不必先修改line_cache RAM或查询接口**。这一归属澄清不影响设计方总体路径判断。

RTL中对应的可审查表达式位于core的RUN/SIM_RUN缺失行分支：行选择使用 `hit_a ? query_b : query_a`，既写入已有 `load_row`，又在同拍直接参与 `*960 + slot_base`。可复用已有load_row寄存器，把命中相关选择与地址乘加放到不同周期。网表N节点无逐节点到RTL交叉表，本回复不把每个N编号硬绑定到某条源表达式；上述方案依据可见起终点、query/hit网络及源码组合链。
