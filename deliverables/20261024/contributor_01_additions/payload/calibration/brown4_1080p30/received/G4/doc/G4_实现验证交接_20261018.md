## 2. 实现范围与逐拍行为

相对 G3 实现提交 `3e50aae`，4 件生产 RTL 中只修改 `source/rtl/undistort_core.v`。map/cache/bilinear、全部原有 21 件 TB/runner、冻结外部接口和精度/超时判据不改。新增状态 `READ_ADDR=11`，沿用原 `load_row/load_bank`，未修改 RAM 组织或缓存替换算法。

```text
FIFO → 行号换算 → cache 标签比较 → 缺失行选择 → load_row/load_bank 寄存
                                                           ↓ READ_ADDR
                              source_slot*2^20 + load_row*960 → addr/req 寄存
                                                           ↓ READ_REQ
                                          req&&gnt → cache_load_begin → READ_WAIT
```

|阶段|行为|检查点|
|---|---|---|
|C0 选择沿|RUN 普通 miss、RUN 预取或 SIM_RUN miss 锁存行/银行/返回状态，转 READ_ADDR|req 保持 0；gnt 预高不记访问、不加载缓存|
|C1 地址沿|只用锁存的 load_row/source_slot 计算 24bit 字地址；len=119 与 req 同沿更新，转 READ_REQ|不以新 FIFO 头重算，不存在 req 携带旧地址的提前受理|
|请求等待|保持 req/addr/len，直至 req&&gnt 同沿受理|cache_load_begin、loads、replace_cursor 按原受理沿更新|
|返回等待|原路径接收 120 个 256bit 有效拍，返回无回压|首拍最早为受理后 1 拍；支持原行为允许的 valid 间隙|

`map_issue` 增加 READ_ADDR 允许条件；预取时 `sample_dispatch` 同样允许 READ_ADDR，仍由命中、sample_phase 与 FIFO 条件门控。load_row/load_bank 在 C0 固定，预取推进 FIFO 头不会改变本次地址。SIM_MODE、统计口、参数快照、源槽 hold/rel 与像素标记保留原语义。map 的相对 V1.2 延迟仍为 +4 拍。

G4 在普通行加载前增加 1 拍；恒等预取可隐藏大多数附加周期，强畸变不可据此类推。该更改只针对 G3 读地址关键链，不代表吞吐或 DRM 缺口已修复。

## 3. 新协议 TB 的覆盖与边界

新增 `sim/undistort_core_g4_protocol_tb.v` 和对应 `.do`，单一 8ns 时钟、Verilog-2001。TB 用层次设置内部状态并强制部分 hit/map_valid 控制，隔离检查调度协议；不将它作为独立全图算法 golden。像素正确性仍由未改的独立 real golden 与 T1/T2 检查。

- MODE=0 RUN 完成 29 笔事务，MODE=1 SIM_RUN 完成 26 笔；覆盖槽 0–3、行 0/1/1079、miss-a/miss-b 与不同替换银行。
- gnt 预高、0–3 拍等待、req/addr/len 保持；无提前请求、提前 cache_load_begin 或提前 loads 计数；锁存行/银行保持。
- 首有效数据精确延迟 1/16/64 拍；120 个连续返回拍逐拍接收并检查目标银行全部 120 项；另测 valid 间隙。
- 每种 MODE 各 2 个异常突发（early-last / missing-last）：须报错、标签无效、不误报完成，复位后恢复。
- 预取 READ_ADDR 继续 map_issue/像素派发；改变 FIFO 头不污染锁存地址；授权位于 consume_x=1918/1919/下一行 0，检查行统计与 current_line_loaded。
- READ_ADDR/READ_REQ/READ_WAIT 分别复位并发起后续有效事务；重复 start/参数快照/帧间清理由原 T7 覆盖。
- FAULT=1 在 READ_ADDR 强制提前 req，使用同一检查器必须报 `FAIL err=33`；runner 识别后输出 `EXPECTED EARLY-REQUEST FAULT DETECTED`。这份 FAIL 是有意的负向证据，不属于正常用例 PASS，不应从归档删除。

开发期间首次 TB 未等待层次赋值的组合逻辑稳定，造成旧地址比较误报；补足检查前的仿真稳定时间后，RTL 无额外改动，最终新跑日志通过。首次失败原始结果保留在 `verification/dev_notes/g4_first_protocol_failure.txt`，仅为开发历史，不混入最终验收日志。

## 6. 复现、观测与预期

**验证方法：** 将完整包解压到英文路径，ModelSim win64 加入 PATH；从 sim 目录依次运行 `run_undistort_map.do`、`run_undistort_map_g3_equiv.do`、`run_undistort_line_cache.do`、`run_undistort_core_g4_protocol.do`、`run_undistort_core.do`，用 `vsim -c -do <脚本> -l <新的transcript>` 并保存完整 console。结果须新生成并检查 PASS/预期故障，不能只看退出码。`collect_g4_evidence.py --run-dir <运行根目录>` 需保留 Git 历史的仓库，可验证 G3 基线和运行副本；ZIP 内 TSV 可独立校验，不要求接收方有 Git 历史。

**观测信号：** state、load_row/load_bank、source_slot、o_corr_rd_req/addr/len、i_corr_rd_gnt/vld/data/last、cache_load_begin、replace_cursor、prefetch_active、map_issue/sample_dispatch、consume_x/y、current_line_loaded、o_stat_* 与 o_pix*/源槽 rel。

**预期与实测：** C0 无请求、C1 同沿寄存正确地址与 req；等待稳定、受理唯一、120 拍返回完整；预取跨行和复位不污染请求。正常协议与冻结 suite 已满足上述检查，故障注入按预期 FAIL。强畸变吞吐、资源与真实时序的未闭合项如下，不由仿真 PASS 推导。
