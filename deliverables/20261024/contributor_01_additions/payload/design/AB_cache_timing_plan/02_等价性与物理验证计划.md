# 等价性与物理验证计划

2026-10-24。以下均为P1获准并实现后的计划，当前未执行新候选RTL仿真或PDS。本次只做原件SHA核对、原生报告读取、预算算术和抽象代数检查。

## 1 输入隔离和执行次序

1. 保存完整原A+B审验包和输入身份。以core `9ba7d1e4…`及cache `4fc449dc…`为唯一对照，新建候选目录；不在参考源码或生产工程上改。
2. P0作为可审查中间提交，只归并逐槽last_use写入优先级。P1再引入done_mask，保持全部状态转移和输出周期。对两个阶段分别保存diff；不要求为每个编辑重复大规模回归。
3. 新增直接针对变换的cache双实例逐拍对照／断言。局部验证通过后再跑已有受影响回归。阶段失败即定位，不启动后续耗时物理流程。
4. 通过RTL功能和周期门禁后，执行明确命名的**相同seed2单次诊断**，工具、器件、速度等级、FDC、IP、频率与基线保持一致，只变获准cache。不得同时加入UART补约束、G8映射或其他优化，避免无法归因。
5. 完整读取综合、map、PNR、四角时序、资源两表和告警，再判断是否需要下一步。seed2改善不是多seed验收；A+B不自动继承G7/G8八种子规则。

若在SP6.4执行，应使用同版本的基线与候选对照或明确跨版本比较限制，记录build和工具SHA。不能把SP6.1基线与SP6.4候选差异全部归因于RTL。

## 2 局部等价判据

新增验证只针对本次状态重编码及写入结构，不能只重复最终像素检查。

- 对合法lookup序列，在Q_DONE边沿前断言done_mask与四个最终qid的ID集合完全相等。
- 成功解析前k个键后，done_mask等于该前缀集合；失败重试不新增位，下一轮Q_SELECT和复位／frame_clear按计划清理。
- 双实例相同激励下，已定义的last_use、tag、victim选择、fetch FIFO及其更新边沿逐拍一致。未初始化且无效的数组单元保留原语义，不能用人为初始化掩盖差异。
- 协议输出busy/done、IDs（done有效时）、fetch请求和地址／长度、load完成／错误、sample_valid及有效像素逐拍一致；错误场景沿用原约定。
- 原Q_ELIG的qfound/qid保护、pending门控、`last_use < retired_count`比较、沿前读取和older平局次序不变。

## 3 新增定向用例

| ID | 激励 | 必须观察到的结果 |
|---|---|---|
| P1-F01 | 四键均命中且四ID不同 | E0受理到E7完成的推导与实跑一致；done_mask恰含四ID；done及last_use同原拍 |
| P1-F02 | 四ID全相同、成对相同、三同一异、交叉重复 | 重复ID只产生集合并；qseq写值及所有输出与基线一致 |
| P1-F03 | x=63/64、127/128、1918/1919；rowA=rowB=0 | 横向跨段、末像素钳位及同一行不漏记或多记ID |
| P1-F04 | 命中与miss交替，最后一个键走Q_ALLOC | 最终chosen在进入DONE前已入mask；不得使用旧qid；Q_ALLOC当拍last_use仍写 |
| P1-F05 | 无可淘汰槽，经历多次Q_ALLOC失败及Q_CHECK重试 | 掩码仅包含成功解析键；不凭失败chosen置位；无新增取数 |
| P1-F06 | qwhich=0缺失，后续键在Q_SELECT已命中同奇偶集合的可淘汰槽 | 该未来命中槽仍由原qfound/qid保护，不被空或部分done_mask遗漏 |
| P1-F07 | touch与DONE同拍，部分ID相同、部分不同；重复touch ID | 相同槽qseq覆盖touch_seq；其他touch槽正常更新；不依赖宿主通常互斥来删功能 |
| P1-F08 | touch与成功ALLOC同拍；touch_seq大于／小于qseq | chosen槽保持原qseq优先级，不做max；其他槽保持touch写入 |
| P1-F09 | Q_ELIG与touch同拍，age恰好等于retired_count | 淘汰仍读沿前值；等于阈值不满足严格小于条件；不增加隐式forwarding |
| P1-F10 | 多个eligible同age／invalid优先场景 | 保持原older第二操作数胜出及原分组树顺序，chosen、DDR轨迹一致 |
| P1-F11 | 在每个查找状态及最后解析边沿插入reset/frame_clear | 新mask无跨帧残留；原输出、样本管线和错误处理语义不扩大，不额外承诺原来未定义的core-only清空能力 |
| P1-F12 | 连续lookup、同键高速touch、奇偶切换及frame切换 | mask不带入上一lookup；宿主缓存ID复用不受影响；prepared/consumed/retired关系不变 |
| P1-F13 | cache端口允许范围内的序号边界，合法/非法ID边界 | 保持22位定义与原输入处理规则；不基于常见1080p最大序号擅自缩位；非法输入结果按原契约记录 |
| P1-F14 | load返回、sample、touch和lookup交织，含原R3晚返回 | RAM别名／pin保护、错误last、单在途及旧排空规则保持；不新增DDR安全承诺 |

负例验证应至少证明能检出：最后ID漏置、掩码不清、旧qid误用、touch优先级反转、用mask替换protected_id。只在隔离故障副本中注入，不能污染候选或参考。

上述表格是待实现测试设计；本包`design_algebra_checks.json`的192组／256组检查只支持符号优先级和集合关系，未覆盖时钟事件、X态、RAM读写或RTL代码生成。

## 5 周期与性能门禁

P1声称只改变内部表示，因此首选判据是相同原AB输入和服务策略下，valid/IDs/DDR请求、最终周期和统计逐拍／逐项一致。不能以“最终图像一样、模型仍有30fps”为由接受新增周期；不一致先定位原因，若确需改变周期则另提契约影响。

既有共享模型对照值：

| 用例 | 原AB周期 | 像素数 | 假设125MHz fps |
|---|---:|---:|---:|
| identity | 4,147,474 | 2,073,600 | 30.138827 |
| real_fast | 4,147,517 | 2,073,600 | 30.138514 |
| real_stress | 4,161,672 | 2,073,600 | 30.036005 |

每个用例仍独立报告cpp、模型fps和实际时序。共享压力cpp=2.006979仍未满足≤2检查；此次等价时序优化并不承诺解决该吞吐指标。任务清单中的模型恒等≥30、真实≥25、目标30与严格≤2检查分别展示，不互相替代，不擅自修改正式阈值。

## 6 物理检查及效果归因

保留新候选所有阶段原件和失败/中断记录，至少包含工具版本/SHA、argv/cwd/PID/起止/退出、前后输入SHA、SNR/PRR/RTR/CSV/holdfix、ADF/数据库/网表、FDC/PCF、资源表和警告。

对照不只看WNS：

1. 原qid→last_use长路径是否消失／缩短；寄存掩码是否真的生成；不是通过false_path、多周期或降低时钟消失。
2. 检查新sel/chosen→mask、mask→last_use、mask clear/reset、touch_ids→last_use、qseq/i_touch_seq数据分发、Q_ELIG/age树和map路径；记录新增最差端点及其逻辑／布线延迟。
3. 逐角报告setup/hold以及异常约束覆盖。单seed目标为所有相关setup/hold满足原要求；任一角仍负即仍失败。该结果也不直接等于最终整机/多seed/板端通过。
4. 两张原生资源表严格核对；整机及core/cache分层LUT/FF/DRM/APM均给差异，不允许以±1/2容差掩盖差异。
5. cache基线8 DRM、合同上限12；目标不增加图像DRM/APM。即使未超上限，如实际增加RAM或改变推断方式也必须解释。不能只说“多192FF”，忽略控制LUT、复位网和复制开销。
6. 原UART自动放置/电气失败、共享引脚和其他未约束问题独立保留。时序改善不关闭E02，也不允许生成/下载位流。

若同seed2仍失败，只给实际失败和下一建议，不能自动扫种子或扩大到P2/P3/P4。多seed范围及最终生产晋升另由管理方／用户裁定。

## 7 回退和输出

回退点R0为本包锚定的原A+B输入；R1为逐槽写入表达审查完成；R2为P1全部局部/整机功能证据完成；R3为单seed物理诊断完成。中间失败均保留证据并回到最近可信点，不覆盖原工程或旧日志。
