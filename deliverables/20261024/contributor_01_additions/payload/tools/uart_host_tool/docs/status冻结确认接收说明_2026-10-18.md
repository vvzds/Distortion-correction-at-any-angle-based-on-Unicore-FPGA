## 差异核对及落实

| 事项 | 与当前实现对照 | 本次动作 |
| --- | --- | --- |
| 位段及两组样例帧 | JSON 四个业务字段、字节序、checksum 与确认书一致 | U4 保留两组完整9字节回读帧及原始字/字段值比对 |
| 保留位 [15:10] | JSON 列出了 reserved，前版会单列其值；确认书要求不解析 | 保留原 JSON 字节，不再提取或显示该保留字段；32bit 原始 hex+dec 照常显示 |
| 快照时点 | 请求受理时刻快照 | 文档按该时点解释，不当成主机收完应答时的状态 |
| frame_busy | core 处理状态，非写出/发布完成 | 不用 busy 下降沿判断发布；不对真实运行期 busy 做精确取值断言 |
| pub_count | 16bit 自然回绕 | 显示无符号计数；手工/脚本比较用 `(new-old)&0xFFFF`；本工具未新增轮询功能 |
| JSON 可选 | 原始32位回读不依赖文件 | 保持不指定 --status-map 时只显示原始字 |
| params_valid | 按权威确认书，为现行组G02校验状态 | 0 不能单独证明已经停机；应结合 busy 和多次发布计数观测，合法组生效后可重启 |

JSON 的 `version=1.2` 表示设计/协议基线，确认书自身 `V1.0` 是文档版本，
二者并不矛盾。确认书中的“--status 解析”按任务书可裁量 CLI 沿用现有
`read-0x05 --status-map`，无需改 UART 帧格式或另建同义命令。

## 使用

```powershell
python uart_tool.py read-0x05 --port COM3 --status-map status_map.json
```

活动样例 0x00040312 显示版本0x12、valid=1、busy=1、pub_count=4；
停机样例 0x00070012 显示版本0x12、valid=0、busy=0、pub_count=7。
reserved 不单列；固定样例不构成实机运行期 busy 必须为1的断言。

新交付包：`uart_host_tool_v1.0_statusfreeze_20261018.zip`。旧 statusmap 包保持不变。
源码/交付副本/解压副本自测及哈希证据随新包交付。此次仅更新主机解析、
自测和文档，未修改 FPGA RTL、冻结接口或任何协议字节。

确认书明确其 I0–I7 证据来自 corr_top V1.0.1 + stub 结构版的设计方联调；
本机没有独立复跑该联调，也没有进行真实串口或上板验证。
原始 param_mgr 附件的 tx/ty ±256 与协议 ±4096 差异仍单独保留，不由 status 确认书推定已修改。
