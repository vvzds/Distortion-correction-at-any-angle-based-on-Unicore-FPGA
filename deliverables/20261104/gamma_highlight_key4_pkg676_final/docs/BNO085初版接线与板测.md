# BNO085纯IMU旋转补偿初版（2026-10-31）

此版本替代JY901P计划，使用用户描述的**GY-BNO085、10针模块**，安装方向为：以镜头向前，传感器**+X向后、+Y向右、+Z向上**。目标仍是1920×1080@30fps、固定1.5倍裁边、原FPGA去畸变/双线性/HDMI路径，上位机根据IMU姿态下发旋转补偿，暂不分析图像旋转。平移、近景视差的视觉辅助不进入初版。

当前阶段为软件/仿真/编译；开发板正在用于其他工作，本轮没有打开串口、JTAG或采集卡。真实接口、供电、轴向、帧率、反应时间和补偿效果均须后续板测，不能用JY901P数据或此前视觉版验收替代。

## 采用SPI和两种姿态报告的原因

FPGA直接管理SPI、低有效INT和RST；以125MHz时钟记录中断及相机源帧事件，及时服务传感器。现有板载USB串口继续连接上位机，不增加正常运行时PC接口。

- 默认`game`：Game Rotation Vector（0x08）＋校准角速度（0x02），均请求200Hz。四元数直接进入姿态历史，避免欧拉角回绕和俯仰奇异点。Game不使用磁力计修正航向，减少磁干扰导致的突然回正；代价是长期航向漂移，S/R可重新锁参考。
- `arvr-game`：AR/VR Stabilized Game Rotation Vector（0x29）＋校准角速度，同样请求200Hz。可比较传感器内部平滑修正的观感及延迟。
- `girv`：Gyro Integrated Rotation Vector（0x2A），通道5同时带四元数和角速度，保留为实验选项。内部参考可能涉及磁力计、配置和预测，不把它当默认方案，也不在本版更改FRS。通道5没有普通报告的时间基字段，本版使用中断时刻，需重新测量时延。

200Hz是请求值，需要通过Get Feature响应及板上姿态包计数验证；芯片可按内部离散频率调整，不承诺恰好200.000Hz。SPI约0.977MHz、mode3（CPOL=1、CPHA=1）、MSB先发，低于手册3MHz上限。没有直接用1kHz作为初版目标，视频仍是30fps，先验证200Hz输入与实际时延的收益。

## 精确接线表

以下均为**MES-FMC-LPC-IO V1.1扩展子卡的J3**，不是核心板上同名连接器。已依据子卡手册第9页核查100H可用针脚，与当前相机及板载串口不冲突。N/P只是网络名，按独立LVCMOS33使用。

| GY模块丝印 | SPI作用/方向 | 扩展子卡J3 | FPGA管脚 |
|---|---|---:|---|
| VCC | 模块供电，先核实此模块3.3V输入方式 | 39或40，A3V3 | 电源 |
| GND | 共地 | 37或38 | 地 |
| SCL | SCK，FPGA→模块 | **33** | **AA25** |
| SDA | MISO，模块→FPGA | **35** | **W24** |
| ADO/AD0 | MOSI，FPGA→模块 | **36** | **V24** |
| CS/CST | 低有效片选，FPGA→模块 | **34** | **Y25** |
| INT/INTN | 低有效中断，模块→FPGA | **29** | **AC26** |
| RST | 低有效复位，FPGA→模块 | **30** | **AB26** |
| PS1 | SPI选择，固定高，接模块3.3V逻辑电源 | 39/40的3.3V（核实电平后） | 电源 |
| PS0 | 上电选SPI，之后低有效WAKE，FPGA→模块 | **27** | **U16** |

**SDA是MISO、ADO是MOSI**。用户文字中的“SCL/SDA/ADO”按BNO085芯片复用表解释，尚无该具体GY板的原理图/实物照片证据；接线前应核对板上的芯片网络、丝印和模式焊盘，避免将标称相似的不同转接板当作同一版本。

PS1/PS0须在复位时均为高，直到首次INT有效；PS0之后由FPGA作WAKE。**不要把PS0再硬接3.3V**，否则FPGA拉低时会短接。若模块带PS焊桥/下拉，先核对电路，不把上拉下拉直接短路。BOOTN需保持正常运行高电平，未引出则检查模块板上默认拉高，不能进入DFU模式。

GY模块是否内置稳压器、VCC可否直接接3.3V，以及逻辑电平，仍需确认。芯片本身VDD/VDDIO推荐上限3.6V，不能根据“模块可能支持5V供电”给FPGA信号接5V。必须确认FMC对应Bank也是3.3V；J3电源针是3.3V不等于该Bank必然3.3V。沿用原相机已核实配置，未确认前不盲目改J20/J24。关闭板卡主电源再接线，不与其他供电适配器双供电；线尽量短并配地线。

## 固定安装方向

相机坐标为X画面右、Y画面下、Z沿镜头向前。外参已经写入`calibration/bno085_mount.json`：

```text
camera_from_sensor = [[ 0, 1, 0],
                      [ 0, 0,-1],
                      [-1, 0, 0]]
```

该矩阵行列式+1，将传感器X映射为相机-Z，Y映射为相机+X，Z映射为相机-Y。程序接受用户声明的安装方向，`physical_axis_trial_completed=false`明确表示尚未实测；必须先做正负小角度测试再高速运动。传感器固定于摄像头同一刚性支架，不能独立摆动。软件中使用外参，不向传感器写安装方向FRS或永久tare。

## 软件和位流

JY901P版本已保留标签`imu-jy901p-initial`及独立交付包。BNO位流使用新的SPI管脚，与JY901P位流不能互换。原已验收视觉预览`host/board_trial.py`和备选一号保持可回退。

本版新增/使用：

- `source/rtl/bno_spi_byte.v`、`bno085_bridge.v`：上电、复位、中断、SHTP收发、Set/Get Feature、产品查询、姿态/角速度及时间戳快照。
- `host/bno085.py`：BNO快照、四元数、诊断和离线SHTP参考解析。
- `host/bno085_trial.py`、`start_bno085_trial.cmd`：预览和纯IMU控制入口。
- `tools/imu_probe.py --sensor bno085`：只开指定板载串口，不开采集卡、不发送矩阵的诊断工具。
- `sim/bno085_bridge_tb.v`、`tools/check_bno085.py`：模拟传感器及离线姿态/控制检查。

专用位流为`release/pango_undistort_bno085_r1.sbit`，身份文件为`release/bno085_manifest.json`。

下载必须选**BNO专用manifest**。只有板卡释放、连线核对完成后才执行，初版用SRAM，不写开发板Flash。

```powershell
# 板卡释放、接线确认并启动PDS JTAG server后，临时下载到SRAM
python tools/program_sram.py --manifest release/bno085_manifest.json --output reports/board_runs/bno085_first_download

# 串口诊断：不改变显示矩阵，不开采集卡；FPGA自身会配置BNO易失报告
python tools/imu_probe.py --sensor bno085 --port COM9 --seconds 5 --output reports/imu_runs/bno_probe01.json

# 对采到的纯串口运动日志做离线姿态/gyro方向一致性检查
python tools/analyze_bno085_log.py reports/imu_runs/bno_probe01.json

# 实际HDMI采集预览，默认Game四元数+角速度、滚转、1.5倍裁边
python host/bno085_trial.py --port COM9

# 滚转通过后试小幅俯仰/偏航的一阶仿射近似
python host/bno085_trial.py --port COM9 --mode affine

# 比较BNO内部平滑方案
python host/bno085_trial.py --port COM9 --bno-report arvr-game
```

COM9为既往板载CP2102端口，实际接入需重新确认。SPI无串口波特率设置，不能传`--imu-baud`来配置BNO。`--bno-report`模式切换会令FPGA复位并重新配置传感器，改变参考系，需重新按S取参考。只读诊断若不指定`--bno-report/--restart-bno`，不会额外请求模式切换或复位；但FPGA每次下载/复位自主初始化仍存在。

快捷键：**S/空格**静止时锁参考，**R**重新锁定，**X**关闭补偿并保持1.5倍裁边，**P**冻结矩阵，**G**Gamma开关，**Q/Esc**退出并尝试恢复自然去畸变画面。预览显示的是与显示器同一路HDMI采集画面，Python只缩放窗口，不额外旋转图像。

## 等待开发板期间的工作与后续返工点

1. 先完成协议、四元数/外参、模拟SPI传感器、纯IMU控制及PDS完整编译；等待期间不占硬件。
2. 板卡可用后先电平/连线，再下载和产品识别，核对报告类型、配置读回、实际包率、INT响应和错误计数。
3. 以约5°正负滚转/俯仰/偏航确认符号，默认安装应表现为：绕光轴主要改变传感器X轴，俯仰主要Y轴，水平偏航主要Z轴；正负还需结合右手规则和画面核对。若模块轴丝印与芯片约定不同，调整外参/适配层。
4. 滚转20°、较快运动、停稳，检查回正、30fps、漂移、HOLD和黑边，再开启小幅俯仰。
5. 用实际日志标定时延，再比较`game/arvr-game`；仅有明确数据时再考虑`girv`。不在正常板测期间盲目写FRS或升级模块固件。

可预见的返工：具体GY模块供电/模式焊桥、SPI读取策略差异、超长启动公告/分片、四元数方向或既有模块FRS方向、时间偏置及Windows调度。这些均未实测，采用保守错误检查和独立版本保留便于调整。

## 主要限制

- 姿态通过四元数走完整SO(3)，但FPGA仍是**二维仿射采样器**；仅滚转能用固定比例刚性补偿，小幅俯仰/偏航用中心一阶近似，默认倾角限15°。大角度透视、平移视差、逐行曝光畸变不能靠它精确消除。
- BNO采样时间用INT时刻与SH-2 timebase/delay修正，优于单纯串口到达时间，但没有硬件曝光触发。相机事件仍为源帧DDR写完；下一帧提前量、曝光年龄和内部融合延迟仍需标定。没有逐源帧编号绑定矩阵的完整闭环。
- Game模式航向可漂移；不使用视觉航向修正，因此不能承诺长期绝对锁定。固定1.5倍裁边仍不能保证任意角度都无黑边。
- 完整SHTP cargo最多512字节载荷；长包会被排空并记错，continuation分片本版拒绝，不把残缺四元数当有效报告。若实物持续使用分片，需补充重组。SPI本身无CRC，采用长度、序号、配置确认及主机四元数范数/时效检查；不能声称有传感器侧CRC校验。
- 传感器重启会改变generation，上位机停止补偿并要求重新锁定。断流/越界保持最后矩阵，恢复新数据时若未复位可继续；电脑或串口彻底断开时恢复命令无法保证到达。

## 资料依据

用户链接指向的CEVA《BNO08X Datasheet》1000-3927 v1.17，59页，页码11协议选择、12～13管脚、18～19 SPI/WAKE/中断、31～32姿态类型、40～42安装/tare、43～44配置、45电平、47～48时序、50速率。LCSC直链与SHA256记入`reports/bno085_sources.json`。

## 本轮编译与离线验证结果

2026-10-31，完整构建`bno085_spi_r2_seed3`通过PDS多角静态时序全部约束；125MHz主时钟域慢角建立WNS为+0.483ns，仍含0.4ns建立不确定度。慢角最小跨域建立裕量+0.239ns、最小保持裕量+0.136ns。器件映射为LUT 11,886/66,600，FF 15,135/133,200，DSP 61/240，DRM 84.5/155。数据是实现报告，不代表实际吞吐或端到端延迟实测。

首轮发现BNO超时控制路径-0.125ns，第二轮将计时差计算流水化修复，没有放宽时钟约束。ModelSim覆盖SPI模式3、初始化、配置读回、时间戳、畸形包、模式切换和复位；Python覆盖安装外参、四元数、纯IMU控制、断流保持、复位后参考失效，旧视觉及JY主机离线回归也通过。报告在`reports/bno085_build_r1/`，该目录名表示BNO初版发布，合格实现是其中记录的r2构建。所有这些检查均未访问实际硬件。

## 首次实板通信及滚转方向修订（2026-10-31）

重新接线后产品信息读回成功（软件版本4.2，部件号10003171，build548），姿态/gyro间隔均读回5000us，实测约199.99Hz；协议错误、序号缺口和超长包均为0。首轮转动反馈为相机约10°、画面约20°，说明补偿同向叠加，尚未通过图像补偿验收。

运动日志中四元数增量与body gyro一致（正常约定RMS误差0.0313rad/s，取逆约定0.7422rad/s），保持sensor→world约定。为当前显示链路在BNO安装配置增加`roll_sign=-1`，仅改变roll模式采样方向，不反转四元数或角速度。离线特征点检查通过，实物复测待确认；单凭该现象不能判定是模组轴丝印、实际安装还是图像链路镜像造成，不能将此系数直接套用于俯仰/偏航仿射模式。后者仍需独立方向标定。FPGA位流未变。

## 滚转初步板测通过（2026-10-31）

滚转方向修正后，用户反馈“初步测试效果不错”。FMC子卡意外脱落后，用户断电重新安装并上电；重新下载同一BNO位流，产品识别及5000us配置读回成功，姿态约199.97Hz、通信错误0。恢复Game/roll、1.5倍裁边、Gamma开启的预览后，用户反馈“我觉得效果很好”。将此记录为滚转补偿的主观初步验收，证据及源文件哈希见`reports/bno085_roll_board_acceptance.json`，保留版本标签`bno085-roll-accepted-20261031`。

此反馈尚不覆盖俯仰/偏航方向、长期漂移、定量残余角度或端到端延迟；安装配置的完整物理轴向验收仍保持未完成。没有改变FPGA位流或写入Flash。

## 裁边按钮（2026-10-31）

IMU预览恢复“− 裁边 / ＋ 裁边”，键盘`-`和`+`（或`=`）同效。1.0～2.5倍按0.1倍步进，共16档，默认1.5倍；状态栏显示当前倍数。改变裁边保留参考姿态和已有旋转，OFF/PAUSED状态也可以调整；调节经同一串口控制线程在FPGA帧界生效。固定裁边不随运动自动变化。裁边越大视野越小，不能保证任意角度无黑边。

## 实测安装映射统一修订与仿射测试（2026-10-31）

用户报告关闭补偿时抬头物体向下、右转物体向左。独立动作日志中抬头主要为sensor Y=-3.159°，右转主要为sensor Z=-3.151°。结合已通过的滚转反向补偿，将有效安装映射修订为`[[0,-1,0],[0,0,-1],[1,0,0]]`，其det=+1。该映射等效于原声明安装绕sensor Z转180°，描述有效坐标X向前、Y向左、Z向上；不能据此断言实物丝印或模块内部FRS原因。原声明映射保存在JSON的`declared_camera_from_sensor`中。

临时roll_sign恢复+1，纯滚转输出与此前通过的旧映射+roll_sign=-1完全一致，已用多个正负角度验证；四元数与gyro约定不变。根据两次真实姿态记录回放，抬头采样向下、右转采样向左，方向检查通过。程序以`--mode affine`启动小角度组合测试，仍限制15°倾角；这部分视觉效果需用户确认，不能仅因离线符号检查通过就宣布验收。

## 用户暂停板测及仿射初测反馈（2026-10-31）

用户原话：“抬头后无明显变化，右转时画面有十分微小的画面局部拉伸感，滚转时画面基本稳定。请先记录并暂停板测”。逐项记录在`reports/bno085_affine_trial_feedback_20261031.json`。不将“抬头后无明显变化”自行解释为定量补偿通过；小幅偏航局部拉伸原因尚未定位，完整仿射模式尚未验收。按用户要求关闭预览，释放串口/采集卡，暂停后续硬件操作，等待明确恢复指令。
