# JY901P 纯IMU旋转补偿初版

目标：沿用已经验收的1080p30、固定1.5倍裁边与去畸变通路，JY901P经FPGA转发到上位机，上位机只根据IMU计算旋转补偿矩阵，再通过同一板载USB串口下发。画面预览直接显示HDMI采集卡，不在Python内变形。视觉旋转估计不参与本版；平移和近景视差辅助后续独立增加。

## 压缩实施安排

不重新组合视频工程，保留备选一号与已验收1.5倍版本。先完成当前无需开发板的工作，编译与上位机开发重叠进行。

| 阶段 | 预留时间 | 完成标准 |
|---|---:|---|
| 串口接收、时间戳、查询与波特率选择 | 约1小时 | 校验、重同步、旧协议兼容仿真通过 |
| 上位机姿态历史、安装外参、纯IMU控制和预览 | 约1～2小时 | 合成姿态与附件原始记录离线通过 |
| PDS综合、布局布线和时序检查 | 约0.5～1.5小时，后台进行 | 同一源码快照有完整时序通过报告和位流哈希 |
| 板卡释放后：接线、轴向、提频和小角度试验 | 约0.5～1.5小时 | 先验证方向和频率，再比较动态响应 |
| 时延调参、俯仰模式、打包 | 约0.5～1小时 | 记录实测边界、恢复操作和已知限制 |

目标在数小时内提供可测试初版。实际传感器提频方式、安装和板卡可用时间是外部依赖；不能把未验证的10Hz输入当作高速验收。跳过长时环境扫描与大规模参数搜索，保留必要的协议、方向、失联、时序与图像链路检查。

## 初版具体范围

- FPGA接收WitMotion的11字节包，校验后保存最新角速度和欧拉角。无排队转发，无画面标记。
- 32位微秒时钟记录包头接收与相机源帧写入完成事件；查询返回一致快照。时间戳约71.6分钟回绕，主机采用有符号差处理。
- 姿态包计数由FPGA产生，上位机漏读快照不误判为传感器低频。
- 同一板载串口继续接收原矩阵命令，新查询0x22、接收波特率设置0x23互不混发，保留原0x10/0x20/0x21。
- JY901P连接只读三线。接收波特率可选9600、19200、38400、57600、115200；更改的是FPGA接收端，**不改变传感器设置**。
- 使用旋转矩阵/四元数插值处理±180°边界；最新姿态之后最多短时角速度预测，默认上限25ms，禁止长时间积分补画面。
- 默认滚转模式：固定缩放、刚性旋转，不根据图像改变比例或剪切。俯仰/偏航模式用旋转单应矩阵在画面中心的一阶仿射近似，倾角默认限15°。
- 不再使用视觉版本的700像素/秒限速或FPGA逐帧半步收敛；新矩阵依然只在视频帧边界生效。
- 传感器断流、样本过旧、预测越界、姿态超限时保持最后矩阵；X关闭、P冻结、S/R重新取参考。上位机正常退出或异常时尝试恢复自然去畸变画面。若电脑/串口本身中断，FPGA仍保持最后配置，不能保证恢复命令到达。

## 接线与机械安装

使用**MES-FMC-LPC-IO V1.1扩展子卡的J3**，不是核心板上同名排针。摄像头原连接不变。

| 传感器 | 子卡J3 | 本版作用 |
|---|---|---|
| VCC | 39或40，3.3V | 单一电源 |
| GND | 37或38 | 共地 |
| TX | 35，LA13_N / FPGA W24 | 输入`imu_rx`，LVCMOS33 |
| RX | 暂不连接 | 初版无发送/配置通道，36/V24留作后续 |

断电接线，确认针1与针号、对应IO Bank为3.3V、传感器TX电平兼容后再接信号；不能仅凭J3电源脚是3.3V推断IO Bank电压。移除CH340，避免双电源/发送端并接。不要为本版盲目改变已工作的FMC电源跳线。IMU和摄像头必须固定在同一刚性支架上，单独手持传感器没有稳定意义。

## 安装方向配置

复制`calibration/imu_mount.example.json`为本机安装配置。`camera_from_sensor`将传感器向量转到相机坐标：相机X向右、Y向下、Z沿镜头拍摄方向。它必须是行列式+1的旋转矩阵，禁止把翻转单轴当作旋转。

例如只有在传感器X向画面右、Y向画面下、Z向拍摄前方时才使用单位矩阵。其他安装方向依据三轴实测填入。先确认传感器报告欧拉角满足`Rz(yaw) Ry(pitch) Rx(roll)`、角速度为传感器本体系，再将`verified`改为`true`。附件没有证明该姿态约定；代码中的它是待板测验证的适配假设。没有验证标记时可看画面和数据，S锁定会被拒绝。

JY901P后续更换BNO085时，可复用姿态历史、相机外参、矩阵计算与预览，但必须更换传感器协议/总线接收层，不能视为电气或协议直接替换。

## 程序运行

只在板卡和采集卡可用、下载对应IMU位流后运行。本说明不表示已经板测通过。

```powershell
# 当前已知9600/10Hz模式，仅看连通性、画面和轴向诊断
python host/imu_trial.py --port COM9 --imu-baud 9600 --mount calibration/imu_mount.local.json --allow-low-rate

# 传感器已经通过核实的方法配置为115200、至少100Hz后
python host/imu_trial.py --port COM9 --imu-baud 115200 --mount calibration/imu_mount.local.json

# 滚转验证完成后，再试小幅俯仰/偏航
python host/imu_trial.py --port COM9 --imu-baud 115200 --mount calibration/imu_mount.local.json --mode affine
```

也可用`start_imu_trial.cmd`传入上述参数。COM9是既往板载串口，不自动猜端口。程序不会安装驱动、修改传感器、自动下载位流或自动开始锁定。采集卡默认按Hagibis设备身份选择，也可显式指定`--camera INDEX`。Gamma默认关闭以匹配最近板测程序，G可切换。

快捷键：S/空格锁参考，R重锁，X关闭补偿并保留1.5倍裁边，P冻结矩阵，G切换Gamma，Q/Esc退出并尝试恢复不裁边的自然去畸变画面。锁参考时相机应静止。

不占采集卡、也不改变显示矩阵的串口诊断：`python tools/imu_probe.py --port COM9 --imu-baud 9600 --seconds 5 --output reports/imu_runs/probe01.json`。仅当明确执行时才打开指定串口。程序不会向IMU发送配置。

默认要求姿态输出至少80Hz，目标100Hz；界面显示的姿态速率来自板上包计数。当前9600、10Hz若不加诊断选项会拒绝启用补偿；即使允许诊断，也会受25ms预测和样本时效保护，可能显示HOLD，不能用于高速效果验收。

## 板测顺序

1. 保留当前其他功能的位流及恢复方式，确认板卡已经释放。下载IMU专用SRAM位流，不写Flash。
2. 三线只读接入，选择已知9600，观察角度/角速度、错误计数、姿态包率与源帧计数。
3. 固定相机与IMU，分别正负小幅滚转、俯仰、偏航，核对三轴和补偿符号。验证后更新本机安装配置。
4. 核对型号/固件支持的配置协议及RX电平，再用已验证方式提频、提波特率并读回；本版代码没有编造未核实的传感器配置指令。目标100Hz角速度与姿态。
5. 先滚转±10～20°，再加快，检查回正方向、抖动、HOLD、画面30fps和黑边。后试±5～10°俯仰，再考虑15°边界。
6. 调时延，一次只改一个参数：`--source-age`（默认16.7ms）、`--packet-delay`（默认0）、`--command-lead`（默认33.3ms），必要时缩小预测上限。录日志分析超前/滞后，禁止为追求反应快任意增大预测。

## 时间关联的边界

FPGA记录的是**接收包头时刻**，不是IMU内部采样时刻；源帧事件是DDR写完，不是曝光触发。上位机从最新完成源帧推算下一帧的曝光姿态，默认加一个30fps帧周期提前量，扣除曝光中点到DDR完成的估计时延，再补包传输/内部时延。矩阵计算/串口下发通常发生在该下一帧处理前，但Windows调度和USB抖动会影响它。

因此这是可标定的初版近似，**还没有逐源帧编号绑定矩阵、也没有硬件曝光同步**。不能把同一时钟时间戳说成已经实现精确曝光同步。若板测中快速运动仍错相位，优先测这些时延；必要时再实现按源帧编号排队应用，而不是提高预测量掩盖问题。

## 当前不承诺的效果

- IMU不扩大镜头视场；1.5倍裁边不能保证任意滚转和俯仰都无黑边。
- 单个全局仿射无法精确消除大角度俯仰透视、不同深度物体视差或逐行曝光畸变。
- IMU本身存在零偏、磁干扰/航向漂移、算法内部延迟；本版没有自动视觉航向修正。
- 离线测试证明协议和数学在约定下自洽，不能代替安装方向、输出频率、实板性能和真实延迟验收。
