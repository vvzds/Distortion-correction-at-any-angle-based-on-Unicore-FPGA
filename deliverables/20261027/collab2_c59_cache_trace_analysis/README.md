# C59 mapped-key cache capacity analysis (2026-10-27)

The unmodified C50/C53/C57 `undistort_map.v` generated 2,073,600 valid mapped keys for the exact 15-degree and 90-degree calibrated test parameters. ModelSim reported `TRACE PASS pixels=2073600` for both. The full local traces have SHA256 `596C425EDCC1437599AD22DCE4DF62B510B47B37A10C9E5212D80276DAAAC5CE` (15 degrees) and `005F3DCBDA1AE559DAE08A9372B54273E8409878EED822BF1A39A2F443F30733` (90 degrees). Each is 20.7 MB and regenerated with `map_trace_tb.v` rather than stored in Git. The source map RTL has SHA256 `89E31CC0CBB9D149523CE908DFB9104CE5A8FC5A6CB35762DCAC597E05475731`.

`analyze_cache_trace.js` replays all four bilinear source-segment keys per output pixel through the RTL's row/segment XOR hash. It uses perfect LRU bookkeeping with eight ways per set and tests 32, 64, and 128 sets, matching the C57, C60, and C61 hardware geometries. `evidence/cache_scenarios.json` and `evidence/rotate90_cache_scenarios.json` are the generated results.

| Tag capacity | 15-degree raster LRU misses/full frame | 15-degree alternating-line LRU misses/full frame |
| ---: | ---: | ---: |
| 256 (C57) | 475,750 | 213,166 |
| 512 (C60) | 54,637 | 21,880 |
| 1024 | 13,242 | 13,242 |

The maximum distinct keys in one output scanline is 466. For the first 1,673,417 output pixels, the 256-tag LRU model predicts 388,049 misses, only 149 (0.038%) more than C57's 387,900 segment loads at timeout. This agreement supports cache-capacity thrashing as the dominant large-angle limitation. C60's actual 46,330 full-frame loads are lower than its 54,637 LRU-model misses: its round-robin/protection policy performs better on this trace, so LRU is a comparison policy, **not** a lower bound. C61's 13,255 actual loads are close to its 13,242 LRU-model misses. Alternating scanline direction would require output reordering and is an architectural option, not current hardware behavior.

The 90-degree trace has up to 2,160 distinct keys in one output scanline. At 1024 tags, raster LRU still predicts 584,771 loads per complete frame, consistent with C61 timing out after only 158,148 output pixels and 46,713 actual loads. Alternating output-line direction reduces the 1024-tag model to 84,478 loads but requires an output-order buffer and remains unproven at 30 frames/s. This is evidence that further simple cache growth is a poor substitute for a tiled source traversal and ordered output writeback.

`analyze_tiled_trace.js` simulates column-major processing inside output strips followed by a separate raster-order readback. At 90 degrees, 32-line strips with 256 tags yield 45,408 LRU misses versus 1,176,481 for raster traversal; 16-line strips yield 82,171. At 15 degrees, the corresponding 32-line/256-tag count is 27,463 versus 475,750 raster. One 32-line RGB565 output buffer requires 122,880 bytes, and double buffering requires twice that before control and cache storage. The `evidence/rotate15_tiled_scenarios.json` and `rotate90_tiled_scenarios.json` files list strip heights 1-32 and 256/512/1024 tags. This is a strong locality direction, but a real design must prove that output-buffer writes, ordered readback, DDR contention, resource fit, and routed WNS sustain the target frame rate; miss counts alone do not.

This is a cache replacement model, not a DDR-cycle or frame-rate prediction. It omits pinning, pending fetches, bank-write contention, route timing, and display order. C60 and C61 targeted simulations are recorded in their own directories. C61 still requires routed setup/hold and later board validation before it can replace C50. C57 used 29.5 of 155 DRM units at device mapping, but this figure alone does not prove that an enlarged cache will route or meet WNS.

To reproduce in an ASCII-path scratch directory, compile `map_trace_tb.v` with `../collab2_c57_cache_wns_trial/rtl/undistort_map.v` and run ModelSim to produce `map_keys.hex`, then run `node analyze_cache_trace.js map_keys.hex cache_scenarios.json` and `node analyze_tiled_trace.js map_keys.hex tiled_scenarios.json`. Add `+ROT90` to the ModelSim run for the 90-degree trace. The testbench defaults to the same 15-degree Q16.16 parameters as the C57 full-system test. The raw output order remains raster; the JavaScript models alone vary traversal for comparison.
