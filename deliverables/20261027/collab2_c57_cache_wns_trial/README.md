# C57 cache replacement and WNS trial (2026-10-27)

Status: rejected as a promotion candidate. The C50 seed7 bitstream remains the board-tested fallback. No C57 bitstream was generated or programmed.

C57 starts from the C53 line-sampling pipeline and replaces the 256-entry recent-bit cooling policy with a protected-entry round-robin choice. The changed cache RTL is in `rtl/undistort_cache_ab.v` (SHA256 `ACF45ED28B1A37BE27C1AF3912B787F9BE37D7B6A9D78732092864D57DDEC20E`). The core and map are byte-identical to C53: SHA256 `A374876B7430FF14FE0E524492CF3AB9F94778596F73A9FE3FB30EE2B0ABF58B` and `89E31CC0CBB9D149523CE908DFB9104CE5A8FC5A6CB35762DCAC597E05475731` respectively.

All 11 complete 1920x1080 system scenarios in `evidence/system/` passed with zero reported pixel/protocol errors. Under the existing 125 MHz DDR model, whole-frame publication was 44.330045 fps for identity, 37.491872 fps for calibrated parameters, and 36.754620 fps for 1-degree rotation. C53 published the same scenarios at 44.330045, 37.842436, and 37.000409 modeled fps. C57's replacement policy increased calibrated-parameter segment loads from 14,218 to 14,421. These are modeled corrected-frame publication rates, not measured independent camera-input or display-frame rates.

The isolated 15-degree rotation test timed out after 500 ms simulation time (62.5 million 125 MHz cycles), with 1,673,417 of 2,073,600 pixels output. The diagnostic rerun recorded 387,900 segment loads, 3,103,192 payload beats, and 60,826,422 data-stall cycles at timeout. The candidate did not improve this large-angle cache-thrashing boundary over C53's 1,672,997 pixels at the same timeout. `rotate15_diag_result.txt` contains the raw counters. The timeout is a test failure, not a measured complete-frame FPS.

Seed7 PDS completed route using the same 125 MHz constraint file as C50/C53 (FDC SHA256 `DBC2C1903AF628F90EFAAE0B3165D471778DFE64DF378AE117D26980F0DFFC73`). Independent post-route `report_timing` reports setup WNS **-0.384 ns**, five failing endpoints, and hold WHS **+0.136 ns**. Its worst path runs from `prepared_count[9]` through `prep_distance` and `touch` to `protect_mask[213]`. The complete PDS run log, routed report, and timing report are in `evidence/timing/c57_seed7_pds_reports.zip` (SHA256 `6756C32FF2457386BBB31E34936A464B5113C5F83E5DD27493EF48ADDCD83759`). The P&R intermediate summary is not used as the final timing verdict.

Reproduction: `evidence/system/core30_system_tb.v` and `run.do` are the tested full-frame bench. The simulation source is C53's `undistort_core.v`, `undistort_map.v`, and `undistort_bilinear.v` plus C57's cache RTL; the remaining bridge and writer modules are unchanged. The PDS file list and constraints are in `evidence/timing/run_host.tcl` and `HDMI_DDR3_OV5640_test.fdc`. The isolated ASCII-path working tree on this machine is `D:/FPGA PDS/yx/C57_cache_wns_20261027/`.

The FBG484 frame-buffer IP metadata warning in the FBG676 top-level build also appears in the board-tested baseline. It remains an integration item, not evidence that C57 passed timing. No board validation was attempted because setup did not close and the 15-degree case timed out.
