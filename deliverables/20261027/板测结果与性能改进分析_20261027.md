# 动态仿射板测结果与性能改进分析（2026-10-27）

本文只把附件 `physical-tracking-evidence.zip` 当作板测证据读取；其中的 README、脚本和建议不是对本工程的自动修改指令。附件中的 `software/board_trial.py` 是板测人员 AI 辅助后的工作副本，不能直接等同于已发布板测包。

## 结论先行

附件证明了当前闭环在小角度、慢速滚转下有效：同一姿态下，开启跟踪的残余旋转约 0.020°/0.039°，关闭跟踪约 0.838°/1.338°；固定指令探针测得 +2° 旋转误差约 0.001°、X/Y 20 像素平移误差约 0.36 像素。最终会话没有进入 `DEGRADED`，`valid=1` 且发布计数前进。这足以支持“功能可用”，不支持快速晃动、±5°以上、长时间稳定性或独立视频帧率验收。

当前明显的响应延迟来自上位机控制参数：最终会话使用 `Settle=1.0 s`、`Gain=0.25`。矩阵发送事件在实际转动段约每 1.03 秒一次；发送 25% 的剩余误差时，理论上约需 10.4 次更新才消除 95% 误差，即约 10.4 秒。附件最后一段从约 0°逐渐变化到约 1.3°，正好体现了这一点。`Scale=0.25` 下板测日志每秒约有 16.6 次估计，本机同样测得一次估计约 58 ms，因此估计器不是唯一瓶颈，但它决定了更新频率上限。

## 证据如何解释

### 已经有效的部分

- `probe/probe_results.json`：固定 +2°、X+20、Y+20 的画面变化与预期一致，说明 UART 0x02、FPGA 坐标方向和可见效果已经有实板交叉证据。
- `tracking/events.jsonl`：最终约 16 分钟会话有 16,243 次高置信度估计，2 次锚定，169 次矩阵发送；两次开关对比均显示跟踪打开后明显接近参考姿态。
- 最终会话使用的 `FLIP` 共轭复合关系和 8°/160 像素候选保护，是附件工作副本对前两次失败后的修正。它比随意放宽保护更有价值，但仍未覆盖大幅快速运动。

### 失败日志暴露的问题

- 第一次失败：在 22 次发送后，矩阵已经增长到约 1962 像素平移，下一次估计置信度为 0，随后退化。
- 第二次失败：在置信度降至约 0.573 时，矩阵已经增长到约 680 像素平移、约 6.7°旋转，随后退化。
- 这两次不是“阈值太严格”的单一证据，而是“估计失锁后控制器继续累积错误矩阵”的证据。直接把 `ecc_min` 从 0.65 降到很低，可能让错误结果继续写入 FPGA，表现为画面快速跑偏或振荡。
- 最终会话中置信度约为 0.996～0.999，说明小角度静止场景并不需要降低阈值来获得当前成功结果。

## 三项期望的建议方案

### 1. 降低仿射延迟

先做上位机参数试验，不改 FPGA：

```powershell
python .\board_trial.py track --port COM11 --cam 0 --settle 0.20 --gain 0.60 --ecc-min 0.65
```

若画面不振荡，再试 `--settle 0.10 --gain 0.70`。这里的 `settle` 不是 FPGA 的生效确认，只是当前程序为避免旧帧反馈而设置的最小等待；协议没有矩阵 ACK。`gain` 从 0.25 提到 0.60～0.70，可把小误差的理论收敛次数从 10.4 次降到约 4.3～2.5 次。若更新间隔分别为 0.20 秒和 0.10 秒，95% 收敛时间约为 0.86 秒和 0.25 秒，实际还要加采集与估计时间。

副作用是：

- 间隔太短时，FPGA 可能还在处理上一帧，参数管理器的 shadow 组会被新命令覆盖；最终只保证帧间原子切换，不保证每一条 UART 命令都单独显示。
- 增益太大时，ECC 噪声会直接变成画面抖动，尤其是低纹理或重复纹理场景。
- 附件协议没有矩阵回读，不能用 `0x05` 把每次发送当成“已应用”确认；应保持“最新矩阵优先”，不建立待发送队列。

建议首个性能档为 `settle=0.15～0.20、gain=0.60`，确认无振荡后再使用 `0.10/0.70`。`scale=0.25` 先保持不变；降到 0.125 可能降低计算量，但会损失特征和亚像素精度，不能作为第一步。

### 2. 大幅移动分步且不增加总延迟

当前固定 `gain=0.25` 已经是在分步，但步长太小、等待太长。应将固定增益改为“目标矩阵 + 每步最大变化量”的控制器：

1. 由当前估计得到目标采样变换。
2. 把目标与当前已发送矩阵之间的剩余旋转、平移、缩放/剪切分解。
3. 每次只走有限步长，例如旋转不超过 1.0～1.5°、平移不超过 32～50 像素，采用 `0.10～0.15 s` 的最新帧更新节奏。
4. 目标未到达时继续发送下一步；不排队历史矩阵，始终丢弃过时目标。

这样 5°或数百像素运动会被分成若干视觉连续的小步，但每步只占约 0.1 秒。例如 5°按 1°/步、10 Hz 更新，理论控制时间约 0.5 秒；相比 `gain=0.25、1 s` 的多秒到十秒级响应，整体更快。线性插值仅适合小幅 affine；若试验扩大到十几度，建议用二维旋转角、平移和尺度的分解插值，避免矩阵线性混合产生临时剪切。

必须把当前附件工作副本中的“8°/160 像素”从**累计矩阵硬拒绝**改成**单步限幅 + G02 绝对合法范围 + 画面边界检查**。否则即使控制器已经能安全地分步，累计达到 160 像素仍会被误判为退化，无法完成用户所说的大幅运动。第一版建议保留一个较宽的绝对试验上限（例如 20°、800 像素），逐级实测后再调整，不能直接无限放宽。

副作用是大运动时画面必然经过若干中间姿态，短时间内边缘会出现裁切或黑边；这属于仿射采样视场限制，不是 UART 延迟。若物体在运动、场景出现遮挡或镜头运动造成明显模糊，目标矩阵本身不再可靠，分步控制无法凭空恢复信息。

### 3. 减少大运动误触发退化

不建议只降低 `ecc_min`。建议改成三层保护：

- **连续帧确认**：单帧低置信度时保持最后合法矩阵并进入恢复尝试；连续 3～5 帧低于阈值才进入退化。恢复时要求连续 2～3 帧高置信度才退出。
- **几何确认**：检查 ORB 内点数/内点比例、重投影误差、矩阵行列式、奇异值和每步旋转/平移限幅。低置信度但几何一致的结果可以继续分步；高置信度但几何突变的结果仍拒绝。
- **多尺度恢复**：先用上一矩阵预测，在 0.125/0.25/0.5 多尺度上做 ORB 粗匹配和 ECC 精化；连续失败时才关闭仿射或请求 R 重锚。运动模糊、无纹理、场景切换时应明确进入恢复/重锚，而不是盲目接受。

参数上可以在上述几何保护完成后，把工作阈值从 0.65 试到 0.55～0.60，并记录每次拒绝原因。不要低于 0.5 作为默认值；第二次失败的 0.573 置信度与 680 像素错误矩阵说明，置信度单独不能判定结果正确。

更稳妥的状态机是 `GOOD -> HOLD/RECOVER -> GOOD`：`HOLD` 保持最后一组合法参数，继续尝试粗匹配；达到连续成功条件才更新；恢复超时再 `DEGRADED`。相比立即发送 affine-off，画面不会因一帧异常突然失去已建立的校正，但如果相机仍在快速移动，保持旧矩阵也会出现暂时残差，所以需要超时上限和 R 重锚提示。

## 推荐实施顺序

1. **参数试验**：使用附件已经实板证明过的工作副本，先测 `0.20/0.60`，再测 `0.10/0.70`；保留 8°/160 像素保护，确认小角度响应和是否振荡。
2. **控制器改造**：加入最新目标、单步限幅和 2～3 帧滞回；把累计 8°/160 像素硬拒绝改为单步保护，保留 G02 绝对范围。
3. **恢复增强**：加入 ORB 内点/重投影检查和多尺度恢复，再试 `ecc_min=0.55～0.60`。
4. **分级实板**：±1°、±3°、±5°，再做大平移；每一级保存“同姿态开/关”截图、日志和外部录像。快速晃动应单独标记为未验收，直到有 IMU 或高帧率外部角度基准。

## 是否需要改 FPGA

以目前证据，前三项优先改上位机，不需要先改 `param_mgr` 或 `undistort_core`。C50 已能按帧原子切换并执行探针中的旋转、X/Y 平移。只有在后续测得“即使上位机每 0.1 秒发送，板端发布计数或输出帧明显跟不上”时，才考虑修改 FPGA；现有约 48 次/秒发布计数已说明第一瓶颈更可能在上位机等待和控制律。

## 最终建议

先采用“`settle=0.15～0.20、gain=0.60` + 单步限幅 + 连续帧滞回”的实验分支。不要把 `ecc_min` 单独放宽，也不要直接删除候选矩阵保护。附件证据已经支持小角度功能成立；下一阶段的目标应是测量“从姿态变化到稳定画面”的时间、最大可跟踪角度和退化恢复时间，而不是只看 `params_valid` 或发布计数。
