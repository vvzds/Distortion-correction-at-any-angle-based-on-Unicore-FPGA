## 1. status 32bit 位域定义

拼装源码（corr_top.v L150）：

```verilog
wire [31:0] w_status = {pub_count, 6'd0, w_frame_busy, w_params_valid, 8'h12};
```

| 位 | 字段 | 复位值 | 语义 | 源码锚点 |
|---|---|---|---|---|
| [7:0] | fw_version | 0x12 | 固定 0x12（V1.2 设计/协议版本），恒读 0x12 | corr_top.v L12/L150 |
| [8] | params_valid | 0 | 直连 param_mgr.o_params_valid。1 = 现行参数组 14 参数全部通过 G02 范围校验，引擎允许运行；0 = 现行组越界，当前帧完成后引擎完全停机（V1.0.1 竞态消除后无多余帧），合法组到达自动重启 | corr_top.v L13/L150；param_mgr.v（swap_go 拍整体重算，L330/L339-347） |
| [9] | frame_busy | 0 | 直连 undistort_core.o_frame_busy。1 = core 帧处理进行中；顶层不叠加 rect_wr_if 写出状态（写出尾段以 pub_count 增量观测，见 §3.3） | corr_top.v L14/L150 |
| [15:10] | 保留 | 0 | 恒读 0；工具侧不解析，未来扩充以本确认书升版为准 | corr_top.v L15/L150 |
| [31:16] | pub_count | 0 | 校正帧发布脉冲（i_corr_pub_pulse，链路侧观测信号，单周期脉冲）计数，每脉冲拍 +1，16bit 自然回绕（模 65536），复位清零 | corr_top.v L16/L138-144 |

## 2. 0x05 回发帧格式与快照语义

**2.1 帧格式（既有冻结，此处引用不改动）**：

```text
AA 55 05 04 status[7:0] status[15:8] status[23:16] status[31:24] chk
```

- status 4 字节**小端**（低字节先发）；
- `chk` = 4 个 status 字节的累加和低 8 位（param_mgr.v L401）；
- 下行请求帧 `AA 55 05 00 00`（V1 冻结向量）不变。

**2.2 快照语义（源码级冻结）**：status 快照在 **0x05 帧受理拍**锁存——param_mgr 解析 FSM
在 checksum 校验通过后一拍产生单周期 `disp_valid`（param_mgr.v L221-226，**无 busy 门控、
无延迟调度**）；该拍 `tx_load = disp_valid && (disp_cmd==8'h05)`（L376）即将顶层 i_status
装入 tx_bytes[4..7]（L391-401）。随后 +1 拍加载移位寄存器（L403-412），经 TX_GAP
（2 bit，L374）停顿后开始串行发送。**受理、锁存同拍。**

**2.3 工具侧时点理解**：回发内容反映**受理时刻**的系统状态，而非工具收完回发帧时刻的
系统状态——串行化全程 90 bit ≈ 0.78ms @115200，期间 pub_count/busy/valid 均可能变化
（如恰有一帧完成发布，pub_count +1）。工具判读、脚本精确断言均应按"受理时刻快照"对齐
（corr_top_tb I4/I6 用例即按此语义构造判据）。

## 3. 字段语义细则与工具侧判读指引

**3.1 params_valid 仅在帧间隙变化**：param_mgr 在 swap_go 拍（帧间隙）对影子组 14 参数
整体重算 valid；帧处理期间 valid 保持不变。故受理拍快照的 valid 在帧内是稳定量。

**3.2 越界组行为**：上位机下发越界参数帧时，帧仍被正常接收（无回发、无错误帧），
帧间隙切换为现行组后 valid=0，引擎当前帧完成后完全停机；可经 status 观测确认：
valid=0 + 停机（busy=0 且 pub_count 不再增长）。V1.0.1 竞态消除后越界切换不产生
多余帧——pub_count 停在最后一个完成帧（I6 实测 pub=7 确定性停机）。

**3.3 busy=0 ≠ 帧已发布**：busy 仅反映 core 处理段；core rel（busy 拉低）后 rect_wr_if
写出、commit、发布仍在进行。**帧完成以 pub_count 增量为准**（I6 实测序：busy 先拉低、
pub 后到）。工具侧"等一帧完成"应轮询 pub_count 变化，而非 busy 下降沿。

**3.4 busy 位运行期精确断言不可靠**：0x05 受理拍若落在帧间隙边界附近，受理拍与 busy
变化沿的相对相位不定——工具/脚本不应在引擎运行期对 busy 位做逐拍级精确断言
（corr_top_tb I4 采用宽松判据的原因）；**完全停机后**（valid=0 引擎停转）32bit 全字
确定性可读（I6 精确判据的依据）。

**3.5 pub_count 回绕**：16bit 模 65536 自然回绕，30fps 发布率下约 36.4 分钟回绕一次；
工具侧差值判读按模 65536 解释。

## 4. 验证证据

**验证方法**：integ_ws 顶层联调 TB corr_top_tb（用例 I0-I7），ModelSim 10.7 批仿真，
2026-10-15，corr_top V1.0.1 + stub 结构版。
**观测信号**：0x05 回发帧 status 32bit 内容（经 TB UART 接收 task 解析比对）。
**预期现象**：I4 宽松通过、I6 32bit 全字精确通过、`=== ALL TESTS PASSED (err=0) ===`、
ideal_link 12 项链路断言 0 违例。

| 用例 | 场景 | 实测向量 | 解码 |
|---|---|---|---|
| I4 | 引擎活动期回读 | 0x0004_0312 | pub=4 / busy=1 / valid=1 / ver=0x12 |
| I6 | 越界组完全停机后回读 | 0x0007_0012 | pub=7 / busy=0 / valid=0 / ver=0x12（全字精确比对通过） |

**U4 mock 帧参考**（供工具自测直接使用，按 §2.1 帧格式组装，chk 已验算）：

```text
活动期示例: AA 55 05 04 12 03 04 00 19
停机期示例: AA 55 05 04 12 00 07 00 19
```

（复位后未下发参数时推定读数 0x0000_0012——由各字段复位值合成，未单列 TB 用例，
工具侧可作防御性 sanity 参考，不作为验收判据。）
