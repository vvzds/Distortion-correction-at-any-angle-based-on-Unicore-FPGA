# C63 frame-start pipeline trial (2026-10-28)

Status: simulation verified and routed timing closed. This is an isolated advanced-task-2 experiment, not a board build. C50 seed7 remains the board-tested fallback.

C63 starts from C62 and registers frame-start acceptance plus parameter qualification before asserting `o_corr_src_hold_req`. All distortion and affine parameters, and `identity_mode`, are captured on the same input edge; the next edge enters HOLD using the saved decision. This removes the C62 critical combinational path from `u_param_mgr/o_aff_a22` to the core's hold-request clock enable. The interface expects a frame-start pulse; a level held across an entire frame can request another frame after completion.

The four files in `rtl/` are the candidate implementation. SHA256 of `undistort_core.v`: `3D122EFDF2C183BDE7031F63F65A1F927BA861323CF2DF84EFF9C7765DD76238`. The cache is unchanged from C62 (`ACF45ED28B1A37BE27C1AF3912B787F9BE37D7B6A9D78732092864D57DDEC20E`).

All 11 full 1920x1080 scenarios passed the pixel-accuracy and protocol checks with the 125 MHz DDR model; identity was exact, while calibrated and rotated cases allowed at most one RGB-channel level of error. Modeled corrected-frame publication: identity 44.330045 fps, calibrated parameters 37.491872 fps, 1-degree rotation 36.762576 fps. These are publication rates, not measured independent camera-input or HDMI-display frame rates. `frame_start_tb.v` additionally checks frame-start register latency, parameter snapshot stability after input changes, and rejection of invalid parameters. `evidence/system/` contains the reproducible ModelSim regression and result logs. Run it from an ASCII-only scratch path with `vsim -batch -do "do run.do"`.

The additional 15-degree full-frame test **timed out** at 500 ms simulation time after 1,673,417/2,073,600 output pixels, matching C57's cache-thrashing limit. `evidence/system/rotate15_result.txt` records the failure. Thus C63 closes timing but does not meet the arbitrary-angle real-time objective; the next architecture must improve source locality, likely with strip-wise traversal and ordered output writeback. The ModelSim process itself exits normally on this testbench timeout, so the result file, not the process exit code, determines pass/fail.

The matched seed7 PDS build completed route with the same 125 MHz constraints as C62. Independent post-route `report_timing` shows setup WNS **+0.445 ns** (zero failing endpoints) and minimum hold WHS **+0.064 ns** (zero failing endpoints), versus C62's -0.233/+0.035 ns. Its worst setup path is now inside the cache, from `u_cache/fetch_rd[2]` to `u_cache/load_beat[4]`; the frame-start hold-request path is no longer worst. Reports are in `evidence/timing/c63_seed7_pds_reports.zip` (SHA256 `8F9D30588D15BB7981960DB9288FF09910596F3F934796A2D955800AF73BAE14`), with the constraint file and build script alongside it.
