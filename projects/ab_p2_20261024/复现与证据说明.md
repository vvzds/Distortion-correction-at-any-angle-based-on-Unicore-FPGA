## 2. 功能复现

在本目录的副本中操作，保留原交付证据。Python 脚本从自身位置定位工程。需安装 Icarus Verilog；调整脚本中本机 `TOOL` / `toolroot`，或使用完整帧 runner 的 `--tool-root`。脚本使用空闲 SUBST 盘符，并只清理自己建立的映射。

1. 在副本中将原 `results` 移到另一个留档目录；脚本故意不覆盖既有结果。
2. 运行 `python -B run_equivalence.py`。五组双实例逐拍对照必须全部通过。
3. 运行 `python -B run_negative_checks.py`。五个错误副本应当编译成功，并被断言检出；此处出现的 FATAL 是预期负例。不得把错误副本放入候选源码。
4. 运行完整帧及宿主回归：

```powershell
python -B candidate/run_validation.py --cases identity real_joint legacy_sim integration c6_real_subsystem c6_host_arb --out results/regression_p2 --tool-root '<Icarus app目录>' --jobs 2 --timeout 7200
python -B compare_regression.py
```

若 runner 要求绝对路径，给 `--out` 使用当前副本下的绝对路径。`compare_regression.py`核对原始输入 SHA（只允许缓存变化）、运行参数及完整日志；仅去除 Icarus `$finish` 行的绝对路径，保留其源码行号、仿真时间和其他全部数据。

先运行 `python -B make_equivalence_tests.py` 可重建本轮测试。

本轮使用 Icarus；未声称执行 ModelSim 或形式等价。定向测试的部分元数据场景通过对原版和候选对称设置内部状态建立，其余流量走端口。对照保留未知态，不靠初始化全部 timestamp 掩盖差异。

## 3. 单 seed 物理复现

`physical/host_seed2` 是原始诊断宿主的隔离副本。相对输入身份表中139个输入，只有缓存 RTL 改变。PDS 2022.2-SP6.1 build138931；PG2L100H / FBG676 / -6；125MHz；布局和布线 seed 均为2。

先通过功能门禁和周期比较，再运行 `python -B run_physical.py`。如换机器，调整 PDS 路径；若工具 SHA 或版本不同，应明确记录，不能把跨工具差异全部归因于 RTL。复跑应使用新的输出目录，避免覆盖本轮证据。不要对已生成物理输出的目录重新执行 `prepare_physical.py`。

`analysis.tcl` 只执行 compile / synthesize / dev_map / pnr / report_timing，没有生成位流步骤。原诊断宿主 UART 未约束及电气限制仍保留；不用于板端下载。所有四角 setup/hold、资源、关键路径和告警都需审查，PDS 退出0不等于时序合格。

GUI查看本轮工程可用运行产生的`physical/host_seed2/ab_seed2_analysis.pds`；命令行复现仍以`analysis.tcl`为准。139项原始输入中的`task1_1080p30.pds`保留了历史工具状态/输出时间戳，不能把其中的旧“bitstream完成”字段当作本轮结果。实际本轮没有生成位流。`impl.tcl`是PDS临时生成脚本，可能含SUBST绝对盘符，不是跨机器入口。

## 4. 性能口径

仿真周期对应具体 TB，不能混用共享 DDR TB 的另一组数字。模型 fps 以125MHz假设计算，不能替代实测新帧发布率。保持原行为意味着本次没有修复既有真实压力场景 cpp>2 的问题；单 seed 改善也不等于多 seed 或板端验收。
